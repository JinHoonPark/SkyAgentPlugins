# 토론 후 확정 사항 (사용자 승인 포함)

## 사용자가 승인한 결정 (원문 요지)
- Step 0 보장 방식: (A) description 트리거에 되돌리기 어려운 행동을 넣고, 발동 시 워커·GRAPH.md 없이
  승인만 받고 팀장이 직접 처리하는 경량 경로를 둔다. — 승인
- 6번(스파이크 필요성 판정을 스펙 워커에 통합): 이번에 한다. — 승인
- T5(서로 독립인 질문 묶어 묻기): 포함한다. — 승인
- team-lead 프로필 notes 수정: profile-setup으로 진행한다(저장소 밖 작업, 스펙과 별개로 팀장이 처리).
  6번 적용에 필요한 spec 프로필 notes 변경도 같은 경로로 처리한다.
- 구현 전에 SPEC.md를 먼저 만든다.

## 토론 합의 (근거: nodes/N1.md, N2.md, N1.round2.md, N2.round2.md)
1. 조건부 적용 — 채택. 기준은 N1.round2.md T3 합의 문구(작업 성격 기준, 크기가 애매하면 제한된 1차 조회를
   직접 한 뒤 필요 시 위임, 의존 판단이 불명확하면 Step 5대로 레벨 2). 명시 위임("워커에 맡겨")과
   브레인스토밍 트리거는 유지. 직접 처리에도 승인·검증·실패 보고는 면제하지 않는다.
2. Step 0 — 별도 스니펫 파일 폐기. 위 (A) 방식. N1.round2.md T2 합의 문구.
3. SKILL.md 축소 — "50%" 합격 조건 폐기. 실행 경로별 총 로드량으로 판정. 잔류·이동 목록은
   N1.round2.md T4 표와 N2.round2.md T4 마지막 문단을 따른다. 매 위임에 필요한 값 이관 표·결과/실패 경로
   분리·실패 우선·검토 독립성 3조건은 SKILL.md에 남긴다. FORM.md 견본을 SKILL.md에 인라인하지 않는다.
4. 재독 금지 — "현재 컨텍스트에 그 절의 내용이 남아 있으면 다시 읽지 않는다. 압축·재개·부분 읽기로 없으면
   필요한 절만 읽는다." 결과 파일·실패 파일·GRAPH.md 상태처럼 변하는 파일에는 적용하지 않는다.
5. graph_update.py — 채택. 생성·행 추가·열 변경. 상태 변경 시 mermaid·다른 행 불변, 대상 노드 없음/중복 시
   부분 기록 없음, 버전 읽기 실패 표기, UTF-8, 실패해도 세션 중단 없이 stderr 진단.
   행 추가 시 승인된 구조 변경은 mermaid에도 반영해야 한다는 기존 규칙과의 관계를 정한다.
6. 판정 통합 — N1.round2.md T1 합의 문구. 사용자가 SPEC 확정 뒤, spec notes가 허용하면 같은 스펙 워커가
   스파이크 필요성 판정안을 별도 노드 결과 파일로 낸다. 팀장 공동 판정 유지, SPEC.md에 섞지 않는다.
   마일스톤 필요성은 스파이크 뒤. 스파이크 생략 시 마일스톤 판정까지 notes가 허용하면 같은 워커에 이어 묻는다.
7. 워커 재사용 — 같은 역할·같은 대상 파일·순차·승인된 범위일 때만. 노드별 결과/실패 경로·GRAPH 행 분리,
   labels.node와 한 agentId가 여러 노드를 가리키는 경우의 기록·재개 의미를 정한다. 검토 노드 제외.
8. T5 — "답이 서로 독립인 질문은 번호를 붙여 한 번에 묻고 질문↔답 원문 대응을 보존한다. 하나라도 종속이면
   순차. 필수 답이 모두 오기 전 다음 단계를 기동하지 않는다. 미응답은 승인이 아니다."
9. 제외(후속): patch 흐름 단순화, thinking 등급 조정, GRAPH 생략, 스펙/태스크 통합.
10. 버전: 개발 중 올리지 않는다. 머지 직전 추천·승인(AGENTS.md §5).
11. 검증 방식(팀장 결정): 리뷰의 5시나리오×3회 전후 실측안은 측정 자체가 비용이 커서 기각.
    정적 측정(경로별 실제 로드 문자 합·Read 횟수, 직접 처리·레벨1·레벨2 경로)을 합격 조건으로 하고,
    실측은 대표 2개(짧은 조회에서 워커 0개, 레벨 1 팬아웃)를 1회씩. 실측 못 한 부분은
    "정적 개선, 실제 효율 미검증"으로 보고.
12. 저장소 밖 사실: daemon.mcp.injectIntoAgents=true(전역, 워커에도 Paseo 도구 주입), 에이전트 단위 차단 없음,
    provider 단위 paseoTools {enabled, disabledTools}만 있음. 설정 변경은 범위 밖.
