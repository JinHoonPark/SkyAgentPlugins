# N1 — 2라운드 교차 반박

경로: `SKILL.md`·`references/`는 `plugins/paseo-toolkit/skills/agent-orchestration/` 기준, `presets.md`는 `plugins/paseo-toolkit/references/presets.md`다. ROUND2.md·LEAD.md·nodes/N2.md는 실행 디렉터리 기준이다.

## 추가 사실에 따른 보정

리뷰 첫 턴은 비캐시 733, 캐시 비율 약 97.7%다(`ROUND2.md:6`). 시스템·도구·브리핑의 분해와 대조군이 없어 **31,965 전체를 순수 기동 고정비로 보지는 않는다**. 캐시 출처도 미확인이다. “캐시 정가 약 10%”와 팀장 4~6턴을 일반화하지 않는다(`LEAD.md:10`). 비용은 입력·캐시·출력·추론을 함께 측정한다.

provider별 차단은 **그 provider의 모든 팀장·워커**에 적용된다. “codex 워커만”은 팀장이 다른 provider일 때의 결과이며 역할별 격리가 아니다(`ROUND2.md:9`). 상시 프롬프트가 비었으므로 이번 환경의 충돌 우려는 철회한다(`ROUND2.md:14`).

## T1 — 필요성 판정 통합

**최종 입장: 중재안에 조건부 찬성. 원안 그대로는 진행 불가라는 리뷰 판정을 수용한다.**

수용: 두 판정을 동시에 확정하면 단계 역전이다(`nodes/N2.md:35`, `SKILL.md:103`). 마일스톤 판정에는 실제 순서 의존·중간 결과가 필요하다(`references/level2.md:127`). 초기 권고와 기존 판정을 모두 유지하면 추가 비용이다.

반박: **필요성 판정과 검증 설계는 다르다**. notes의 설계 배제가 판정 금지를 뜻하지는 않는다(`presets.md:240`). 스펙 확정 뒤 판정하고, 필요하면 실험·사용자 확인 뒤 마일스톤을 판정하는 중재안에는 단계 역전이 없다(`ROUND2.md:17`). 모든 통합안이 “진행 불가”인 것은 아니다.

동시에 팀장의 “배제하지 않았다”도 충분하지 않다. 현재는 notes의 **명시적 허용**을 요구하며, 판정안의 담당을 전문 역할로 지정한다(`SKILL.md:240`, `references/level2.md:125`). 스파이크 생략은 마일스톤 판정 역량까지 자동 부여하지 않는다. 이것은 단순 문장 축약이 아니라 담당 역할 변경이다.

합의 문구:
> 스펙 워커가 해당 판정을 허용하는 notes를 가진 경우, 최종 스펙 후보와 함께 스파이크 필요성 판정안을 별도 노드 결과 파일에 낼 수 있다. 팀장은 사용자가 그 SPEC 내용을 확정한 뒤에만 공동 결론을 낸다. 스펙이 바뀌면 같은 워커가 판정안을 갱신한다. 필요하면 전문 역할이 설계·실험을 수행하고 사용자 확인 뒤 마일스톤을 판정한다. 생략이면 마일스톤 필요성 판정까지 허용된 기존 워커에 이어 묻는다. 허용되지 않으면 기존 전문 역할 경로를 유지한다.

판정은 필요·생략·정보 부족과 근거까지다. SPEC에 합쳐 저장하지 않는다(`references/level2.md:102`). 2절·level2·프리셋 역할을 함께 수정하고 실제 notes도 확인한다. **새 세션 절감과 추가 모델 호출 0은 다르다**. 공동 판정·독립성·결과/실패 규칙은 유지한다.

## T2 — Step 0 승인 보장

**최종 입장: 별도 스니펫 대신 위험 행동 트리거와 ‘승인 점검만 수행’ 경로를 채택한다.**

수용: 읽히지 않는 파일이나 완료 보고의 스니펫은 다음 요청의 승인을 강제하지 못한다(`nodes/N2.md:31`, `LEAD.md:24`). 위험 행동을 트리거에 넣자는 리뷰안이 그보다 낫다(`nodes/N2.md:30`).

보완: 트리거가 발동했다고 삭제 한 건을 워커·GRAPH 절차로 보내지는 않는다. 현 Step 0 자체도 레벨과 직교한다(`SKILL.md:143`). description에는 **사용자 요청뿐 아니라 수행 중 새로 계획한 위험 행동도 행동 전에 점검**하도록 쓴다.

합의 문구:
> 직접 처리 여부와 무관하게 git 커밋·스테이징·푸시·태그·브랜치 삭제, 외부 전송, 파일·디렉터리 삭제, 저장소 밖 설정 변경을 수행하기 전에 Step 0을 적용한다. 같은 범위의 명시적 지시는 승인으로 재사용한다. 승인 점검만 해당하면 전제 조회·위임·실행 기록 절차로 진입하지 않는다.

앞부분에 게이트·경로 선택을 두고 부분 읽기를 지원하면 먼저 여기만 읽는다. 전체 로드 호스트에서는 그 비용이 남는다. description이나 미설치 규칙에만 의존하지 않는다. 승인 시점을 직접 경로의 ‘행동 전’까지 확장하되 승인 강도는 유지한다(`SKILL.md:172`).

## T3 — 조건부 적용 기준과 설정 충돌

**최종 입장: 파일 개수보다 입력·출력의 성격으로 정의한다. 설정은 보고만 하되 충돌 해소 없이 적용 완료를 선언하지 않는다.**

수용: 팀장의 구체 기준 필요성 및 저장소 밖 설정 미수정에 동의한다(`LEAD.md:17`, `ROUND2.md:24`). 반박: 파일 10개는 열 줄짜리 파일과 대형 로그를 구분하지 못하며 개수를 알아내기 위한 조사까지 유발한다. 승인·프로필 경계가 불명확한 경우까지 “직접”으로 보내는 기본값도 반대한다(`SKILL.md:152`).

합의 문구:
> 여러 자료의 본문을 연결해 관계·원인을 추적하거나, 대량 로그·명령 출력을 수집·분류하고 핵심 근거만 넘겨야 하는 탐색은 워커에 맡긴다. 이미 좁혀진 경로·검색식으로 위치나 짧은 사실을 확인하는 일은 직접 처리한다. 예상량 확인을 위한 별도 탐색 워커는 띄우지 않는다. 크기만 애매하면 제한된 1차 조회를 직접 하고, 이후 범위가 위 조건에 해당하면 그때 위임한다. 의존·역할 분리·공동 쓰기·판정 의존 중 하나라도 있거나 그 여부가 불명확하면 크기와 무관하게 레벨 2로 간다.

명시 위임·브레인스토밍 트리거는 유지한다. 직접 처리에는 위임 전용 파일 의무를 부과하지 않되 승인·검증·실패 보고를 면제하지 않는다. 정책 변경으로 승인받는다(`nodes/N2.md:30`). team-lead notes와 충돌하므로 실제 적용에는 명시적 예외 지시나 승인된 프로필 변경이 필요하다. 저장소 수정만으로 라우팅 전환 완료를 보고하지 않는다(`presets.md:214`).

## T4 — 지표와 절별 잔류·이동 목록

**최종 입장: (a) 실제 로드량·(b) Read 수·(c) reported tokens를 함께 쓰되 정적 합격과 실제 효율 입증을 구분한다.**

빈번한 규칙은 남기자는 팀장·리뷰 논거에 동의한다(`LEAD.md:26`, `nodes/N2.md:53`). 레벨 2가 반드시 level1 전체와 검토 브리핑까지 읽는다는 계산에는 반대한다. 해당 경로가 요구한 절만 센다(`SKILL.md:485`). 팀장 18,744자와 자문·리뷰 19,243자의 차이는 본문 변경이 아니라 CRLF→LF 개행 정규화로 재현됐다.

합격 기준 세트:
- 같은 입력의 직접 조회·정형 수정·레벨1 팬아웃·레벨2 순차/검토·실패 재개를 전후 비교한다. 최초 읽기와 현재 문맥에 내용이 남은 재사용을 분리한다.
- LF 정규화 후 **실제로 반환된 절의 문자 합**을 재독 포함 집계하고 고유 합도 병기한다. Read 호출 수와 전체 모델 호출 수를 따로 센다. 바이트·UTF-16 길이를 혼용하지 않는다.
- 승인·독립성·결과·실패·재개 검사와 링크/절 검사가 모두 통과해야 한다. 기본 경로마다 로드 문자와 Read 수가 증가하지 않고, 최소 하나가 감소해야 정적 개선으로 인정한다. 예외 경로가 늘면 증가분을 별도 제시해 채택을 판단한다.
- 가능하면 같은 모델·설정으로 팀장+전체 워커의 입력/캐시/출력/추론 및 기동 수를 반복 측정한다. reported input만 줄어도 비용 절감 확정으로 쓰지 않는다. 미측정이면 ‘정적 개선, 실제 효율 미검증’으로 보고한다. **50%는 합격 조건에서 제외한다.**

## T5 — 추가 제안의 이번 범위

**최종 입장: 독립 질문 묶기만 이번 개선 후보에 포함하고 patch·thinking은 후속으로 분리한다.**

수용: 호출 감축 방향(`LEAD.md:11`)에 맞춰 한 번에 한 결정만 묻는 제한을 바꾼다(`references/level2.md:138`). 합의 문구: “답이 서로 독립인 질문은 함께 묻고, 답변을 원문 질문에 대응시켜 같은 작성자에게 전달한다. 미응답은 승인이 아니다.” 확정 게이트는 유지하고 변경안을 승인받는다.

유보: patch는 결과 보존·실패 예산을 바꾸고(`references/level2.md:350`), thinking은 품질 비교·프로필 승인이 필요하다(`presets.md:99`). 동시에 바꾸면 비용 효과의 원인도 흐려진다. GRAPH 생략·스펙/태스크 통합(`LEAD.md:45`)도 기록·역할 변경이 커서 제외한다.

## T6 — 버전과 skill-creator

**최종 입장: 이의 없음.** 리뷰·팀장의 머지 직전 승인 방침을 수용한다(`nodes/N2.md:39`, `ROUND2.md:30`). “마이너 +1”을 미리 확정하지 않는다. 실제 변경의 호환성·규모를 보고 추천한 뒤 승인받는다(`AGENTS.md:53`).

합의 기준: graph_update.py뿐 아니라 본문 분리·참조 추가도 담당 에이전트의 skill-creator를 적용한다(`AGENTS.md:64`). 본문 교체만 하는 편집은 제외한다. 이번 자문은 구현 승인이 아니다.
