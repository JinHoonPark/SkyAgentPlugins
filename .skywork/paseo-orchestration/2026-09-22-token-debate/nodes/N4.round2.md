## 결함 목록

### D8. 중간 — 직접 지시와 워커 지시 충돌의 동작 검증 없음

- 위치: `SPEC.md:17`, `SPEC.md:229-246`
- 근거: 요구사항은 두 지시가 함께 오면 사용자에게 확인하라고 명확히 했지만 A6은 이 경우를 발동/비발동으로 판정할 수 없고, 필수 질의에도 없다. A8에도 확인 질문 전 무동작을 검사하는 시나리오가 없다. D1에서 요구한 세 경계 중 이 하나만 검증되지 않는다.
- 수정: A8에 “네가 직접 처리하되 워커에도 맡겨” 같은 충돌 질의를 추가하고, 통과 조건을 “파일·에이전트·GRAPH 변경 없이 확인 질문을 내고 종료하며, 무응답을 어느 쪽 승인으로도 해석하지 않음”으로 둔다. 이 사례는 이진 트리거 평가 A6에 넣지 않는다.

### D9. 높음 — 리뷰 브리핑의 ‘원본 요구와 대상 경로만’이 필수 항목과 충돌

- 위치: `SPEC.md:35-38`, `SPEC.md:183`, `SPEC.md:246`
- 근거: 검토 독립성은 작성자의 대화·보고를 배제한다는 뜻이지 브리핑의 프로필 notes, 결과/실패 경로, 도구, 출력 제한까지 빼라는 뜻이 아니다. 실제 템플릿은 이 운영 항목을 필수로 둔다(`assets/review-briefing.md:1`, `assets/review-briefing.md:53-68`). 또한 R1-7은 사용자 확정 제약도 합격 기준에 싣지만 A1·A8의 “원본 요구와 대상 경로뿐”은 후속 확정 제약까지 누락시킬 수 있다. 그대로 구현하면 결과/실패 파일 규칙과 판정 기준이 약해진다.
- 수정: A1 D1과 A8-3을 “**변경 내용에 관한 입력**은 사용자 요청 원문·확정 제약·대상 경로로 한정하고 팀장의 보고·대화·해결 방향은 싣지 않는다. review-briefing의 프로필 notes, 결과/실패 경로, 도구·권한, 출력 제한·보고 형식은 그대로 싣는다”로 바꾼다.

### D10. 중간 — 경고 질의를 재실행할 증빙이 보존되지 않음

- 위치: `SPEC.md:232-235`
- 근거: 공식 `run_eval.py`는 질의 실행 예외를 `Warning: query failed`로 stderr에만 쓰고 JSON에는 해당 경고를 표시하지 않는다(`claude skill-creator/scripts/run_eval.py:221-225`, `run_eval.py:247-255`). 현재 명령은 stdout JSON만 저장하므로, 기대값이 비발동인 실패가 JSON에서 통과로 보일 때 어떤 질의를 재실행해야 하는지 사후 확인할 수 없다.
- 수정: 1차·재실행 명령에 각각 `2> <stderr 로그>`를 추가하고 로그도 실행 디렉터리에 남긴다. 경고 줄에서 질의를 특정할 수 없는 경우 해당 1차 평가 세트 전체를 재실행 대상으로 삼는 보수 규칙을 둔다. 결과 JSON 두 개라는 표현은 “재실행 대상이 있을 때”로 명확히 한다.

## Q5 정합성

Q5 자체는 검토 독립성 3조건과 모순되지 않는다. 작성자는 팀장이고 리뷰 워커는 별도 `agentId`이며, 작성자 보고 대신 원본 기준·대상만 받고, review 허용 notes를 요구한다(`SPEC.md:34-39`). description은 직접 수정 뒤의 사건 기반 별도 트리거를 담고(`SPEC.md:229`), `run_eval.py`가 첫 도구 호출만 판정하는 한계는 A6에서 제외한 뒤 실제 다중 단계 A8-3으로 검증한다(`SPEC.md:233`, `SPEC.md:246`). 따라서 D9의 브리핑 문구만 고치면 스킬 밖 직접 경로에서도 검증 가능한 구조다.
