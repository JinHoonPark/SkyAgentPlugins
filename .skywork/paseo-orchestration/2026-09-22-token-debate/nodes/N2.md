# N2 — 1라운드 독립 검증

## 결론

제안의 문제 진단은 대체로 맞지만, 8개안을 그대로 일괄 적용하면 승인 규칙이 비는 경로와 개발 단계 역전이 생긴다. 판정은 **진행 가능 1개(8), 조건부 5개(1·3·4·5·7), 진행 불가 2개(2·6)**다. 특히 “짧은 작업 직접 처리”의 실제 토큰 절감은 정적 글자 수만으로 입증되지 않았다.

## 사실 주장 실측

실행 명령(파일은 `[IO.File]::ReadAllText()`의 UTF-16 문자열 `Length`, 즉 문자 수로 측정):

```powershell
$t=[IO.File]::ReadAllText((Resolve-Path $f)); $t.Length
rg -n -F 'provider를 추측하지 않는다' plugins/paseo-toolkit/skills/agent-orchestration/SKILL.md
```

결과:

- `SKILL.md` **19,243자 / 500줄**: “약 1만 9천 자”는 맞다. 모든 작업·조회도 적용한다는 트리거와 크기 예외 금지도 실제로 있다(`SKILL.md:3`, `SKILL.md:8-9`).
- `level2.md` 17,827자, `FORM.md` 9,013자, `graph-patterns.md` 1,975자, `worker-briefing.md` 1,075자다. `SKILL + level2 + graph-patterns + FORM + worker-briefing`의 **고유 파일 합은 49,133자**로 5만 미만이다. 다만 현재는 승인 직전·실행 기록 직전·기동 보고 직전에 `FORM.md`를 읽으라고 한다(`level2.md:169`, `level2.md:266`, `SKILL.md:425`). 이를 세 번 실제 로드하면 **67,159자**다. 리뷰 경로 고유 합도 **50,834자**, 프로필 폴백 경로는 **61,320자**다. 따라서 “레벨 2는 5만 자 이상”은 최소 고유 일반 경로에 대해서는 867자 과장이지만, 지시된 재독 또는 리뷰·폴백 경로에서는 사실이다.
- 정확 문자열 `provider를 추측하지 않는다`는 **4회**다(`SKILL.md:58`, `SKILL.md:73-75`). 반복 주장은 맞다.
- `level1.md`와 `level2.md`에서 20자 이상 완전 동일한 정규화 행은 **0개**였지만, 경로·생성 시점·`agentId`·상태·mermaid 불변·버전·재시도 규칙이 의미상 반복된다(`level1.md:5-40`, `level2.md:236-281`). 즉 “문장 복제”가 아니라 “규칙 중복”이다.
- “작은 작업의 워커 고정비가 작업보다 크다”는 정적 파일로 검증할 수 없는 가설이다. 에이전트별 실제 입력 토큰·도구 정의·왕복 수 측정이 제안서에 없다.

## 변경안 8개 판정

아래에서 A는 승인 게이트, I는 검토 독립성 3조건, R은 결과 파일 규칙, F는 실패 처리 규칙이다.

| 번호 | 판정 | 회귀 및 저장소 규칙 대조 |
|---|---|---|
| 1 | **조건부** | 제안한 세 조건만 쓰면 “단일 파일 삭제” 같은 짧고 되돌리기 어려운 요청이 스킬 밖으로 빠져 A의 네 범위·직전 승인(`SKILL.md:165-177`)를 잃는다. 조건부 트리거에 **되돌리기 어려운 행동**도 넣거나 동일 강도의 상시 규칙이 먼저 존재해야 한다. 레벨 2 여부를 스킬 적용 전에 판정할 최소 기준도 description에 있어야 한다. I/R/F는 위임하지 않는 직접 처리에는 적용 대상이 아니지만, “워커에 맡겨”와 브레인스토밍 트리거는 유지해야 한다. 기존 동작 약속 변경이므로 사용자 승인 대상이다(`AGENTS.md:24-27`). |
| 2 | **진행 불가** | 플러그인 안에 읽히지 않는 스니펫 파일만 두면 스킬이 발동하지 않는 직접 처리에서 A를 강제하지 못한다. 전역 파일은 수정하지 않는다는 제약 때문에 “상시 규칙으로 분리” 목적을 달성하지 못한다. 새 파일은 구조 변경이므로 `skill-creator`가 필수다(`AGENTS.md:64-78`); 사용되지 않는 보조 문서는 문서 최소화 원칙에도 맞지 않는다(`AGENTS.md:31-34`). I/R/F 직접 영향은 없다. |
| 3 | **조건부** | 큐·값 이관·결과 경로의 세부 문구는 옮길 수 있으나, 실행 경로·권한·승인·성공 여부를 결정하는 핵심은 SKILL에 남아야 한다(`AGENTS.md:82-84`). 특히 R의 성공/실패 경로 분리와 실패 우선 판정(`SKILL.md:346-374`, `level2.md:332-341`), I 세 조건(`SKILL.md:325-344`), A/F 진입 규칙은 요약 삭제하면 안 된다. 파일 추가·본문 분리는 `skill-creator` 대상이다(`AGENTS.md:64-78`). “50%”만 맞추려고 참조로 밀면 총 Read는 늘 수 있다. |
| 4 | **조건부** | 같은 세션의 `FORM.md` 반복 Read 제거에는 직접 효과가 있다. 단, 문서 변경뿐 아니라 **컨텍스트 압축·재개로 필요한 절 내용이 남아 있지 않은 경우**와 처음에 일부 절만 읽은 경우도 재독 예외여야 한다. 그렇지 않으면 A 화면, I 보고, R/F 인수 형식이 오래된 기억에 의존한다. 현재 직전 Read 지시는 위 세 줄에 실제 존재한다. 파일 목록이 그대로면 `skill-creator` 대상은 아니다(`AGENTS.md:66-67`). |
| 5 | **조건부** | A/I/R/F 의미는 바꾸지 않고 기록의 기계적 갱신만 대체하면 가능하다. 새 `graph_update.py`는 구조 변경이므로 `skill-creator`가 필요하다(`AGENTS.md:64-78`). 생성·행 추가·열 변경 외에 **상태 변경 시 mermaid/다른 행 불변, 버전 읽기 실패 표기, 대상 노드 없음·중복 노드에서 부분 기록 없음, UTF-8**을 테스트해야 한다. 스크립트 실패가 세션을 중단시키지 않고 stderr 진단을 남겨야 한다(`AGENTS.md:94-98`). FORM 견본만 비교하는 현재 합격 기준은 F를 충분히 덮지 않는다. |
| 6 | **진행 불가** | 현 순서는 스펙 확정 뒤 스파이크 필요성을 판정하고, 스파이크 뒤 마일스톤 필요성을 판정한다(`SKILL.md:101-108`). 두 판정은 담당 전문 역할 워커와 팀장의 공동 판정이다(`SKILL.md:116-120`, `level2.md:123-134`). `SPEC.md`와 동시에 모두 내면 미확정 스펙과 미실행 스파이크를 전제로 뒤 단계를 선판정한다. 또한 spec 프로필은 기술 검증 설계를 `spike-plan`으로 명시적으로 배제하고, milestone 역할도 별도다(`presets.md:238-256`). A의 단계 게이트와 프로필 경계를 깨며, I/R/F 절감 근거도 없다. 단순 “초기 권고”로 낮추고 후단 판정을 유지하면 중복만 늘어난다. |
| 7 | **조건부** | 같은 산출물의 재작업은 이미 기존 에이전트에 `send_agent_prompt`하는 규칙이 있다(`level2.md:365-408`). 이를 별도 후속 노드까지 넓힐 때는 같은 역할·승인된 대상·범위이며 순차 실행인 경우로 제한해야 한다. 노드별 R 성공/실패 경로와 합격 기준, GRAPH 상태·재시도 횟수는 분리하고, 범위 변경이면 보내기 전 A를 받아야 한다(`SKILL.md:387-395`). 검토 노드는 반드시 다른 `agentId`, 작성자 대화·보고 미전달, review 허용 notes라는 I 세 조건을 유지한다(`SKILL.md:325-336`). 같은 작업의 보완이면 새 노드가 아니라 기존 재작업 규칙을 써야 한다. 파일 목록 불변의 본문 수정이면 `skill-creator`는 불필요하다. |
| 8 | **진행 가능** | 읽기 전용 조사와 보고만 하고 설정을 바꾸지 않으므로 A/I/R/F 회귀가 없다. 현재 저장소 검색에서 `injectIntoAgents` 설명은 `SKILL.md:58-63` 한 곳뿐이라, 실제 Paseo 문서·코드가 저장소 밖이면 근거 출처와 미확인 범위를 보고해야 한다. 설정 변경으로 확대하면 별도 A 대상이다. |

버전 제약은 제안서와 저장소 규칙이 정면 충돌한다. 현재 두 매니페스트는 모두 `0.11.0`이다(`plugins/paseo-toolkit/.claude-plugin/plugin.json:3`, `plugins/paseo-toolkit/.codex-plugin/plugin.json:3`). “마이너 +1”을 개발 중 일괄 적용하면 안 되며, **main 머지 직전** 변경 규모와 추천 버전을 제시하고 사용자 승인 뒤 두 파일에 반영해야 한다(`AGENTS.md:52-57`).

## 합격 기준 5개 평가

1. **SKILL 50% 이하**: 상시 로드 본문 크기만 재는 대리 지표다. 참조로 이동해도 통과하므로 총 토큰 효율을 입증하지 못한다.
2. **링크·절 유효성**: 필요한 구조 회귀 검사지만 토큰 지표는 아니다.
3. **모든 규칙 존재/대조표**: 의미 보존 검사다. 영구 대조표 파일을 새로 두면 문서 최소화·구조 변경 부담이 생기므로 검증 산출물로만 두는 편이 맞다.
4. **graph_update 결과 일치**: 기능 회귀 검사다. 토큰·Read·턴 감소를 측정하지 않는다.
5. **description 조건 포함**: 라우팅 정적 검사일 뿐 오탐·누락과 절감량을 측정하지 않는다.

빠진 핵심 측정은 변경 전후 동일 시나리오별 **리더+워커 총 입력 토큰**, 에이전트 기동 횟수, Read 호출 수·읽은 문자 수, 사용자 왕복 수, 완료까지 시간이다. 최소한 짧은 조회/한 파일 수정/레벨 1 팬아웃/레벨 2 순차·검토/실패·재개의 cold·same-session 두 조건을 비교하고, 승인·I·R·F 회귀 테스트도 통과해야 한다. 한국어 문자 수 대신 실제 사용 모델의 reported input tokens를 써야 한다.

## references 이동 시 매 실행 Read가 되는 내용

- **4절 값 이관 표**: 모든 `create_agent`에 필요하므로 위임 실행마다 읽는다(`SKILL.md:255-281`).
- **5절 결과 파일 경로 상세**: 모든 워커 브리핑 전에 리더가 경로를 정해야 하므로 매 실행 필요하다(`SKILL.md:295-307`, `SKILL.md:346-374`).
- **3절 활성 큐·투입 절차**: 모든 레벨 1 실행에서 필요하다(`SKILL.md:179-229`). 기존 `level1.md`에 합치면 새 파일 Read는 피할 수 있지만 그 참조 자체는 매번 필요하다.
- **GRAPH 공통 규칙**: 레벨 1·2 모두 필요하다. `level1.md`가 거대한 `level2.md` 전체를 읽게 하는 방식은 악화다; 작은 공통 참조로 분리하거나 이미 반드시 읽는 문서의 필요한 절에 둬야 한다.
- **자문 폴백, 8절 시스템 프롬프트 절차, 브레인스토밍 상세**는 해당 경로에서만 필요하므로 지연 이동이 타당하다(`SKILL.md:283-293`, `SKILL.md:455-481`, `SKILL.md:489-499`).

따라서 핵심본 축소는 “파일별 50%”가 아니라 **각 실행 경로에서 실제로 읽는 고유/반복 문자와 모델 입력 토큰의 합**으로 판단해야 한다.
