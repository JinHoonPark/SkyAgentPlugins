# 외부 에이전트 피드백 원문: agent-orchestration 스킬 토큰 사용량 개선

## 대상
경로: plugins/paseo-toolkit/skills/agent-orchestration/
관련 파일: SKILL.md, references/*.md, assets/*.md, scripts/, ../../references/presets.md,
          ../../.claude-plugin/plugin.json, ../../.codex-plugin/plugin.json

## 배경
이 스킬은 팀장 에이전트가 모든 요청을 워커에 위임하도록 강제한다. 분석 결과 토큰 낭비의
주원인은 두 가지다.
1. 작은 작업까지 전부 위임해서, 워커 기동 고정비(시스템 프롬프트·툴 정의 로드, 팀장의
   기동·GRAPH.md 기록·기동 보고·결과 인수 턴)가 작업 자체보다 커진다.
2. description이 "모든 작업 요청 전에 반드시 읽는다"라서 SKILL.md(약 1만 9천 자)가 매 요청
   팀장 컨텍스트에 로드되고, 레벨 2에서는 참조 문서까지 5만 자 이상이 된다.

유지해야 할 잘 된 설계: 브리핑에 본문 대신 경로만 전달, 결과는 파일로 받고 팀장이 본문을
컨텍스트로 옮기지 않음, 모델 확인을 1회 조회로 묶음, 검토 독립성 3조건, 승인 게이트.

## 변경 사항 (우선순위 순)

### 1. 스킬을 조건부로 사용하도록 변경
description과 도입부를 고쳐, 다음 셋 중 하나일 때만 이 스킬을 적용한다.
- 병렬로 나눌 수 있는 작업이 여럿일 때
- 레벨 2 조건(2절 Step 1~5: 입출력 의존, 같은 대상에 다른 역할, 같은 파일 공동 쓰기,
  합격 판정 의존, 판정 불명)에 걸릴 때
- 단일 작업이지만 탐색량이 클 때(많은 파일 읽기, 긴 로그·출력 처리)
그 외 짧은 조회, 한두 파일 수정, 간단한 질문은 팀장이 직접 처리한다.
- "작업 크기로 예외를 두지 않는다"와 "조회해줘도 전부 위임" 문구를 제거한다.
- 경계가 애매할 때의 기본값을 한 줄로 명시한다. [결정 필요 — 기본값: 직접 처리]
- 사용자가 "워커에 맡겨"라고 명시하면 조건과 무관하게 스킬을 적용한다는 예외를 둔다.
- 브레인스토밍 진입(10절)은 기존대로 description 트리거로 유지한다.

### 2. Step 0(되돌리기 어려운 작업 승인)을 상시 규칙으로 분리
스킬이 조건부가 되면 Step 0이 빠지는 작업이 생긴다. 커밋·푸시·태그·브랜치 삭제, 외부 전송,
파일·디렉터리 삭제, 저장소 밖 설정 변경에 대한 승인 규칙을 CLAUDE.md/AGENTS.md에 넣을 수 있는
짧은 스니펫(10줄 이내)으로 작성해 플러그인 안의 별도 파일로 둔다.
사용자의 CLAUDE.md, AGENTS.md, 전역 설정은 직접 수정하지 않는다. 스킬 본문의 Step 0은 유지한다.

### 3. SKILL.md를 핵심본으로 축소
- SKILL.md에는 리더 역할, 발화 규칙 요지, 전제 점검 요지, 레벨 판정 트리, 각 절의 참조 안내만
  남긴다. 목표: 현재 대비 50% 이하.
- 아래는 references로 옮기고 SKILL.md에는 "언제 읽는지" 한 줄만 남긴다.
  4절 값 이관 표와 자문 폴백, 3절 활성 큐·투입 절차 상세, 5절 결과 파일 경로 규칙 상세,
  8절 시스템 프롬프트 추가 절차, 10절 브레인스토밍 상세
- 같은 규칙의 반복을 제거한다(예: 1절 표의 "provider를 추측하지 않는다" 반복, level1.md와
  level2.md에 중복된 GRAPH.md 규칙은 한 곳에 두고 참조).
- 규칙의 의미는 바꾸지 않는다. 문장만 줄이고, 옮긴 규칙이 누락되지 않게 한다.

### 4. 참조 재독 금지 규칙 추가
"같은 세션에서 이미 읽은 참조 문서는 다시 읽지 않는다. 문서가 변경된 경우만 예외"를 추가하고,
FORM.md의 "출력 직전에 읽는다" 지시들이 이 규칙과 충돌하지 않게 문구를 맞춘다.

### 5. GRAPH.md 갱신 스크립트 도입
scripts/graph_update.py를 만든다.
- 기능: 생성(버전 줄 + mermaid + 노드 표), 노드 행 추가, 특정 노드의 열 값 변경
  (예: `graph_update.py set <GRAPH.md 경로> N3 상태=완료 agentId=...`)
- 표 형식은 references/FORM.md의 「실행 기록」 견본과 동일해야 한다.
- mermaid 블록은 상태 갱신으로 수정하지 않는 기존 규칙을 지킨다.
- 버전은 plugin.json에서 읽고, 못 읽으면 기존 규칙대로 그 사실을 적는다.
- 표준 라이브러리만 쓴다. 기존 append_system_prompt.py의 스타일을 따른다.
- SKILL.md·level1.md·level2.md의 GRAPH.md 갱신 지시를 이 스크립트 호출로 바꾼다.

### 6. 스파이크·마일스톤 판정을 스펙 워커에 통합
스파이크·마일스톤 필요성 판정안을 스펙 작성 워커가 SPEC.md와 함께 내도록 바꾼다.
팀장 단독 판정 금지와 공동 판정 원칙은 유지한다. 필요로 판정된 경우에만 설계 워커를 띄운다.

### 7. 같은 파일을 이어 다루는 후속 노드의 워커 재사용
같은 역할이고 앞 노드와 같은 파일을 다루는 후속 작업은, 7절 "원래 역할 워커의 범위 내 후속
보완"처럼 기존 워커에 send_agent_prompt로 이어 맡기는 경우로 넓힌다.
검토 노드는 기존의 독립 검토 3조건을 그대로 적용하며 재사용 대상이 아니다.

### 8. 조사만: 워커 세션의 Paseo 도구 주입 여부
daemon.mcp.injectIntoAgents가 워커 세션에도 Paseo 도구를 주입하는지 문서·코드로 확인한다.
주입된다면 워커용으로 이를 막는 방법이 있는지 조사해 보고만 한다. 설정은 변경하지 않는다.

## 제약
- git 커밋·푸시·브랜치 작업은 하지 않는다. 변경은 작업 트리에만 남긴다.
- 사용자 전역 설정, CLAUDE.md, AGENTS.md를 수정하지 않는다.
- 문서 문체(한국어, 단정형 "~한다")와 절 번호 체계를 유지한다.
- 승인 게이트, 검토 독립성, 결과 파일 규칙, 실패 처리 규칙의 의미를 바꾸지 않는다.
- 두 plugin.json의 version을 함께 올린다(마이너 버전 +1).

## 합격 기준
1. SKILL.md 글자 수가 변경 전의 50% 이하다.
2. SKILL.md와 references의 모든 상대 링크·절 참조가 실제 파일·절을 가리킨다.
3. 변경 전 SKILL.md의 모든 규칙이 새 SKILL.md 또는 references 어딘가에 존재한다(규칙 대조표).
4. graph_update.py로 생성·행 추가·열 변경 결과가 FORM.md 견본 형식과 일치한다.
5. description이 1번의 세 조건과 예외를 담고 있다.
