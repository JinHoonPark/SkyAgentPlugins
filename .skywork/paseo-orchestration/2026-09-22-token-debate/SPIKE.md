# SPIKE — agent-orchestration 트리거 평가·사건 트리거 성립 검증

`claude -p` 호출 상한: U2 12회(질의 10회 + 확인 재실행 최대 2회) + U3 6회 = **18회**. U1은 재실행하지 않고 U2부터 시작해 U2·U3만 실행한다. 상한에 닿으면 그 실험은 거기서 끝내고 남은 항목을 "미실행"으로 적는다. 모델은 전 실험에서 같은 ID로 고정하고(`--model <ID>`) 결과에 기록한다.

## 공통 환경

- 실행 위치: Windows pwsh 7. `$work = Join-Path ([IO.Path]::GetTempPath()) ('skill-trigger-eval-' + [guid]::NewGuid().ToString('N'))`; `New-Item -ItemType Directory -Path (Join-Path $work '.claude')`로 빈 `.claude/`를 만들고 `Push-Location -LiteralPath $work`로 이동한다. 이 디렉터리가 없으면 `find_project_root`가 사용자 홈의 `.claude`를 선택할 수 있다. 기존 환경 값을 보관한 뒤 `$env:PYTHONPATH = Join-Path $HOME '.skywork/skill-trigger-eval'`, `$env:PYTHONUTF8 = '1'`, `$env:PYTHONIOENCODING = 'utf-8'`, `$env:PYTHONDONTWRITEBYTECODE = '1'`을 설정하고, `CLAUDECODE`는 자식 실행 동안 제거한다. 종료 시 `finally`에서 환경과 위치를 복원한다. 생성 파일은 UTF-8(BOM 없음)으로 쓴다.
- 스킬 사본: 저장소의 `plugins/paseo-toolkit/skills/agent-orchestration/`을 격리 디렉터리 `skill/agent-orchestration/`로 복사하고, 사본 SKILL.md의 `description`만 후보 문안으로 바꾼다. 후보에는 다음 트리의 문구·번호·순서를 그대로 담는다(줄바꿈·정렬 공백만 변경 가능): `스킬 적용 판정 — 요청 문장만 보고 위에서부터, 처음 걸리는 곳에서 멈춘다 1. 사용자가 워커에 맡기라고 지시했다 → 적용 2. 요청에 이름이 나오지 않은 파일을 찾아 읽어야 한다 → 적용 3. 로그 파일이나 전체 빌드·테스트 출력을 읽고 해석해야 한다 → 적용 4. 요청에 이름이 나온 대상 파일이 5개를 넘는다 → 적용 5. 요청이 설계·구현·검토처럼 단계마다 따로 산출물을 내며 이어지는 여러 단계를 거쳐야 한다 → 적용 6. 그 밖 → 팀장이 직접 처리 직접 처리 중에 2·3·5에 해당하게 되면 그 시점에 적용으로 바꾼다. 검색식 한 번으로 위치만 확인하는 것은 2의 "찾아 읽기"가 아니다. 명령의 종료 코드·통과 여부만 확인하는 것은 3이 아니다. 팀장이 직접 고친 뒤 붙이는 독립 검토는 5의 단계로 세지 않는다.`
- 후보의 나머지 내용: 팀장을 주어로 한 직접 지시는 트리보다 우선하되 되돌리기 어려운 행동·브레인스토밍 트리거가 우선하며, 직접·워커 지시가 함께면 사용자에게 확인한다. 독립 검토·다른 에이전트 검토 요구는 트리 1로 분류한다. 팀장이 파일을 직접 만들거나 고쳤으면(삭제만 한 경우 제외, 직접 지시 포함) 작업 뒤 이 스킬로 리뷰 워커의 독립 검토를 붙인다. git 커밋·스테이징·푸시·태그·브랜치 삭제, 외부 전송, 파일·디렉터리 삭제, 저장소 밖 설정 변경은 수행 중 새로 계획한 경우도 행동 전에 발동한다. "브레인스토밍하자", "아이디어 좀 내보자", "뭘 만들면 좋을까", "방향 좀 잡아줘"를 담는다. 위임 여부 재질문 없음, 라우팅은 팀장만·워커 재위임 금지, 직접 처리에도 승인·검증·실패 보고 면제 없음(실패는 응답으로 보고)을 담는다. 후보가 1,024자 이하·`<`·`>` 없음·frontmatter YAML 파싱 성공인지 확인한다. 원본·설치본은 고치지 않는다.
- 발동 스텁: U2·U3의 직접 실행은 `run_eval.py`와 같은 형식의 명령 파일 `.claude/commands/agent-orchestration-skill-<8자리 hex>.md`(frontmatter `description`=후보)를 격리 디렉터리에 두고, 본문은 "발동 기록용 스텁이다. `SKILL-TRIGGERED`만 출력하고 다른 도구를 부르지 말고 멈춘다." 한 줄로 한다. description만으로 발동하는지를 재기 위해서다.
- 직접 실행 명령 형태: `$claudeExe = (Get-Command claude.cmd -CommandType Application | Select-Object -First 1).Source`; `$cliArgs = @('-p','"<질의>"','--output-format','stream-json','--verbose','--include-partial-messages','--setting-sources','project,local','--strict-mcp-config','--no-session-persistence','--model','<ID>')`; `$p = Start-Process -FilePath $claudeExe -ArgumentList $cliArgs -WorkingDirectory $work -WindowStyle Hidden -PassThru -RedirectStandardOutput (Join-Path $work '<질의별>.jsonl') -RedirectStandardError (Join-Path $work '<질의별>.err.log')`; `if (-not $p.WaitForExit(120000)) { $p.Kill($true); $p.WaitForExit(); throw '120초 초과' }`. U1-3도 같은 `$claudeExe`를 쓰고 `$cliArgs`만 바꾼다. 시간 초과는 실패로 기록하며 자동 재시도하지 않는다. U2·U3은 사용자 설정·플러그인·MCP를 싣지 않고, 승인 없는 쓰기·명령은 `-p`에서 거부된다.
- 사후 분석: jsonl에서 도구 호출을 순서대로 뽑는 표준 라이브러리 Python 스크립트를 격리 디렉터리에 둔다. **하네스 판정**은 `run_eval.py` 규칙(첫 도구 호출이 명령 파일 이름을 담은 `Skill`·`Read`면 발동, 다른 도구면 미발동)을 그대로 적용한다.
- 스냅숏(각 실험 전후 비교): 기본 동작은 전후 차이를 기록하고 실험을 계속하는 것이다. 차이는 결과에 경로·전후 값·수정 시각으로 남기고, 스파이크로 인한 변화인지는 실행 후 팀장이 판정한다. 스냅숏 비교로 즉시 중단하는 경우는 저장소 상태·파일 해시 변화, `~/.claude/settings*.json`의 존재·해시 변화, `~/.claude/plugins/installed_plugins.json`의 존재·해시 변화 세 가지로 한정한다. 나머지 감시 대상(`~/.claude/CLAUDE.md`, `~/.paseo/config.json`, `commands/`·`skills/`·`agents/`·`hooks/`, `known_marketplaces.json`)의 차이는 기록만 한다. 저장소 루트에서 `git status --porcelain=v1 --untracked-files=all`의 상태·경로를 정렬해 비교하고, 변경·미추적 파일마다 `Get-FileHash -Algorithm SHA256 -LiteralPath <경로>`로 내용 해시를 비교한다(경로 해석은 같은 명령의 `-z` 출력 사용, 이름 변경은 양쪽 경로, 삭제·부재는 별도 표식). 저장소 밖의 감시는 다음으로 한정한다.Windows `~/.claude/settings*.json`(이 PC에는 `settings.json`)·`~/.claude/CLAUDE.md`·`~/.paseo/config.json`의 존재 여부·SHA-256을 비교한다. `~/.claude/commands/`·`~/.claude/skills/`·`~/.claude/agents/`·`~/.claude/hooks/`는 각 경로에만 `Get-ChildItem -LiteralPath <경로> -Recurse -File -Force`를 실행해 정규화·정렬한 파일 경로와 SHA-256을 비교한다. 없는 파일·디렉터리도 부재 표식으로 비교한다(이 PC의 `commands/`·`agents/`는 부재). `~/.claude/plugins/installed_plugins.json`은 존재·SHA-256을 비교한다. `~/.claude/plugins/known_marketplaces.json`은 원본을 수정하지 않고 읽은 JSON의 각 마켓플레이스 항목에서 `lastUpdated`만 제거한 뒤 Python `json.dumps(data, sort_keys=True, ensure_ascii=False, separators=(',', ':'))`로 정규화한 문자열과 존재 여부를 비교한다(파일 해시는 비교하지 않음). 캐시·마켓플레이스 사본 전체는 감시하지 않는다. `~/.claude` 전체 파일 목록을 수집하지 않으며, `sessions/`·`projects/`·`file-history/`·`backups/`·`shell-snapshots/`·`session-env/`·`history.jsonl` 등 Claude 실행 중 쓰이는 파일은 감시 범위에 넣지 않는다.
- 원시 로그는 `.skywork/paseo-orchestration/2026-09-22-token-debate/spike-logs/`(git 무시 경로)로 옮긴다. 종료 시 `$work`의 정규화한 절대 경로가 시스템 임시 폴더 하위인지 확인한 뒤 `Remove-Item -LiteralPath $work -Recurse -Force`로 격리 디렉터리만 지운다. 삭제가 도구 정책에 막히면 우회·재시도하지 않고 남은 절대 경로와 정리 미완료를 결과에 적으며, 정리 실패만으로 실험 판정을 중단하지 않는다. 남은 경로의 정리는 팀장이 사용자 승인을 받아 수행한다. 평가 사본·원본·설치본은 수정하지 않는다.

## U1. Windows 트리거 평가 사본이 한국어 입력으로 격리된 상태에서 동작하는가

- **검증 질문**: (a) Windows의 `claude`·`python`이 있고 Claude 인증이 유효한가. (b) `~/.skywork/skill-trigger-eval/`의 `scripts` 패키지가 로드되고 프로젝트 루트가 격리 디렉터리로 잡히는가. (c) 한국어 description·질의가 깨지지 않고 평가되며 임시 명령 파일이 격리 디렉터리에만 쓰이고 지워지는가. (d) 스텁은 보이면서 설치된 `paseo-toolkit`·`agent-orchestration`은 init의 skills·slash_commands·plugins 어디에도 없어 평가 세션이 격리됐다고 판정할 수 있는가.
- **절차**
  1. (0회) `Get-Command claude,python -CommandType Application`, `claude auth status`, `claude --version`으로 Windows 실행 파일·인증을 확인한다.
  2. (0회) 공통 환경을 설정한 격리 디렉터리에서 `python -c "import scripts.run_eval as r; print(r.__file__); print(r.find_project_root())"`로 수정 사본의 로드 경로와 격리 루트를 확인한다.
  3. (1회) 격리 디렉터리에 스텁 명령 파일을 두고 공통 제한 실행기의 `$cliArgs`만 `@('-p','"ok라고만 답해"','--output-format','stream-json','--verbose','--include-partial-messages','--setting-sources','project,local','--strict-mcp-config','--model','<ID>')`로 바꿔 실행한다(평가 사본과 같은 두 격리 옵션). init 이벤트의 skills·slash_commands 중 하나 이상에 스텁이 보이고, 설치된 `paseo-toolkit`·`agent-orchestration`이 skills·slash_commands·plugins 어디에도 없는지 확인한 뒤 스텁을 지운다.
  4. (2회) 한국어 후보 description의 `skill/agent-orchestration/SKILL.md`와 `smoke.json`을 UTF-8(BOM 없음)으로 쓴다. smoke.json은 `query`·`should_trigger` 객체 배열로 "이 빌드 로그 분석해줘"(true), "`parseConfig` 어디 있어?"(false)를 담는다. 같은 cwd·환경에서 `python -m scripts.run_eval --eval-set .\smoke.json --skill-path .\skill\agent-orchestration --runs-per-query 1 --trigger-threshold 0.5 --timeout 60 --model <ID> > .\smoke.out.json 2> .\smoke.err.log` 실행 후 `$LASTEXITCODE`를 보관하고 `Get-Content -Raw -Encoding utf8 .\smoke.out.json | ConvertFrom-Json`으로 읽는다.
- **통과**: (a) 모두 충족, 2의 모듈 경로가 수정 사본이고 루트가 격리 디렉터리, 4의 종료 코드 0·JSON 파싱 성공·`summary.total`=2, 결과 `description`과 후보를 각각 공백·줄바꿈 정규화(Python `" ".join(text.split())`)한 뒤 일치하고 결과 `description`에 대체 문자(U+FFFD) 없음, 두 `results[].query`는 입력 한국어 원문과 정확히 일치, 인코딩 예외·문자 대체·`Warning: query failed` 없음, 실행 뒤 `agent-orchestration-skill-*` 잔여 파일 없음, 홈 `.claude/commands/`에 새 파일 없음, 스냅숏 불변, 3에서 스텁이 보이고 설치된 `paseo-toolkit`·`agent-orchestration`이 skills·slash_commands·plugins 어디에도 없어 평가 세션 격리가 확인됨. 발동 결과 자체는 판정에 쓰지 않는다.
- **실패**: 실행 파일·인증 미충족, 다른 평가 모듈 로드, 격리 루트 불일치, 스텁 미노출·설치된 `paseo-toolkit` 또는 `agent-orchestration` 혼입·init 정보 부족으로 격리 확인 불가, 정규화한 description 불일치·U+FFFD 검출·질의 한국어 원문 불일치·인코딩 오류, 평가 비정상 종료·경고·파싱 실패, 임시 명령 파일 잔류·격리 밖 생성.
- **중단**: 실행 파일·인증 미충족 또는 실행 중 인증 실패, 2에서 사본·격리 루트 확보 실패, 스냅숏 변화, 3에서 스텁 미노출·설치 플러그인 혼입·격리 확인 불가면 U1~U3의 남은 호출을 전부 중단한다. 한국어 처리 실패 시 U1은 실패로 끝내며 사본을 고치거나 추가 호출하지 않는다.

## U2. 첫 도구 호출 판정이 규칙상 올바른 동작을 실패로 잡는가

- **검증 질문**: 발동해야 할 질의에서 모델이 규칙이 허용하는 사전 동작(검색식 한 번의 위치 확인, 종료 코드·통과 여부만 보는 명령)을 한 뒤 되돌리기 어려운 행동·파일 읽기 전에 스킬을 부르는 경우가 실제로 생기는가. 짧은 질의("이 빌드 로그 분석해줘", "이 에러 원인 찾아줘")가 발동하는가. 단계별 산출물이 필요한 설계·구현 요청과 설계 설명 요청의 발동 여부가 구분되는가.
- **시작 절차(0회)**: 공통 환경의 절차대로 새 격리 디렉터리와 빈 `.claude/`를 만들고 환경 변수·작업 위치·`$claudeExe`를 설정한다. 스킬 사본과 후보 description을 새로 준비해 정적 검사를 하고, 발동 스텁·사후 분석 스크립트와 아래 fixture를 생성한다. 첫 질의 호출 전에 공통 환경의 감시 범위·비교 방식으로 기준 스냅숏을 새로 기록한다.
- **fixture**: `src/config.ts`(`parseConfig` 정의), 오류가 든 긴 `build.log`, `last-error.txt`, 링크가 섞인 `docs/*.md` 30개, `a.py`, `cache.py`(만료 없는 메모리 캐시), 더미 파일이 든 `build/`.
- **질의(각 1회, 10회)**: 발동 — "이 에러 원인 찾아줘", "이 빌드 로그 분석해줘", "docs/ 아래 30개 파일 링크 통일해줘", "네가 직접 build 폴더 지워줘", "네가 직접 브레인스토밍하자", "`a.py` 고치고 리뷰 에이전트한테 독립 검토 받아줘", "`cache.py`에 만료 정책을 설계하고 구현해줘" / 비발동 — "`parseConfig` 어디 있어?", "네가 직접 이 에러 원인 찾아줘", "`cache.py`의 캐시 설계 설명해줘".

## U3. description만으로 세션 도중 발동이 일어나는가

- **검증 질문**: (A) 이름 나온 파일을 고치다 수행 중 삭제가 필요해졌을 때 삭제 시도 전에 스킬을 부르는가. (B) 이름 나온 한 파일을 직접 고친 뒤 검토를 위해 스킬을 부르는가.
