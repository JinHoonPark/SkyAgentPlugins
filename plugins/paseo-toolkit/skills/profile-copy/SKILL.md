# Paseo 에이전트 프로필 전달

Paseo 프로필을 다른 PC로 옮기기 위한, 그대로 복사해 보낼 수 있는 Markdown 핸드오프 블록
하나를 만든다. 이 작업은 현재 PC의 설정을 **읽기만** 한다. 설정 파일을 바꾸거나 Paseo
데몬을 재시작하지 않는다.

## 입력 확인

1. 사용자 홈 디렉터리 아래 `.paseo/config.json`을 읽고 `daemon.agentProfiles` 배열을 찾는다.
   사용자 홈 경로는 실행 환경에서 구한다. 사용자 이름, 드라이브 문자, 절대 경로를 추측하거나
   하드코딩하지 않는다.
2. 배열이 없거나 JSON을 읽을 수 없으면 핸드오프 블록을 만들지 말고, 읽기 실패 사실과 사용자가
   확인할 위치만 알린다. 빈 배열이면 `N`을 0으로 하여 빈 배열을 그대로 전달한다.
3. 배열의 각 객체와 그 안의 `notes`는 원본 그대로 복사한다. 객체를 새로 조립하거나 필드를
   정렬하지 않는다. `id`, `name`, `icon`, `color`, `provider`, `model`, `modeId`,
   `thinkingOptionId`, `notes`의 존재 여부와 값, 그리고 존재할 때의 `featureValues`를 모두
   보존한다. `color`나 `modeId`가 없는 객체에 값을 보충하지 않고, `featureValues`가 없는
   객체에 빈 값을 넣지 않는다.

## 핸드오프 블록 작성

핸드오프 블록을 만들기 직전에 [references/FORM.md](references/FORM.md)의 `## 핸드오프 블록`
절을 읽는다. 그 절의 네 섹션 순서와 `## 지시`의 여섯 항목은 바꾸지 않는다. 사용자가 바로
복사할 수 있도록 완성된 블록만 출력한다.

- 제목의 `N`에는 배열 길이를 넣고, 제목 바로 아래에는 JSON이 원본 설정의
  `daemon.agentProfiles` 배열이라는 설명 한 줄을 넣는다.
- JSON 자리에는 설정에서 읽은 배열 원문을 넣는다. 필드 추가·삭제·순서 변경·값 가공은 하지
  않으며 `notes`도 고치지 않는다.
- `## 특이사항`은 아래 판정을 통과한 프로필이 있을 때만 JSON 뒤에 넣는다. 없으면 이 섹션을
  완전히 생략한다.
- 마지막에는 `## 지시`와 여섯 지시를 원문 그대로 넣는다. 아이콘 매핑 줄의 중괄호 부분은
  이번 배열에 실제로 쓰인 아이콘으로 채우고, 지시 3의 `N`에는 배열 길이를 넣는다.

## 특이사항 판정

배열의 모든 `notes`를 그때 읽고 의미로 판정한다. 프로필 이름이나 미리 정한 문구 목록으로
찾지 않는다. 보낸 사람 PC에만 있는 설정·모델·권한·승인 정책처럼, 배열을 등록해도 받는 쪽에
자동으로 적용되거나 강제되지 않을 내용을 발견하면 해당 프로필을 목록에 넣는다.

각 항목에는 프로필 이름, `notes`에서 해당하는 원문 문구, 그리고 수신자가 배열을 등록했을 때
그 내용이 자동 적용되는지 또는 적용되지 않는지를 적는다. 지원되지 않는 스키마 필드를 암시한
문구와 보낸 사람 개인의 승인 정책은 등록만으로 동작하지 않는 대표 사례다. 이 설명은 JSON의
`notes`를 바꾸거나 축약하는 근거가 아니다.

## 아이콘 매핑

아이콘 이름과 이모지는 새로 정의하지 않는다. 이 스킬 디렉터리 기준
[`../../scripts/manage_profiles.py`](../../scripts/manage_profiles.py)의 `ICON_EMOJI`와
`DEFAULT_PROFILE_ICON_EMOJI`를 읽어 사용한다.

배열의 `icon` 값을 모두 확인해 중복 없이, 이번 페이로드에 실제로 쓰인 아이콘만 한 줄에
`icon=이모지` 형식으로 적는다. 사전에 없는 아이콘 또는 없는 `icon` 때문에 기본 아이콘이
필요한 경우에는 해당 값에 `DEFAULT_PROFILE_ICON_EMOJI`를 적용한다. 이모지 표시는 전달용
목록에만 쓰며 JSON의 `icon` 값은 바꾸지 않는다.

## 범위

이 스킬은 프로필 전달 프롬프트를 만드는 데만 쓴다. 수신자가 프롬프트의 지시에 따라 등록할지,
기존 `id` 충돌을 어떻게 처리할지, 데몬을 재시작할지는 수신 측 사용자에게 확인받은 뒤에만
진행하게 한다.
