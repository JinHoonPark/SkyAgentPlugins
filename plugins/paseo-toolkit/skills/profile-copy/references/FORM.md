## 핸드오프 블록

아래 형식으로 완성된 한 덩어리를 출력한다. `N`, JSON, 특이사항 목록, 아이콘 매핑 줄은
실제 입력으로 채운다. 특이사항이 없으면 그 섹션과 목록을 통째로 뺀다.

````markdown
# Paseo 에이전트 프로필 전달 (N개)

아래 JSON은 `~/.paseo/config.json`의 `daemon.agentProfiles` 배열에 그대로 들어가는 원본 형식입니다.

```json
[
  ...
]
```

## 특이사항

- {프로필 이름} — {notes의 해당 문구}: {받는 쪽에서 자동 적용되는지 아닌지}

## 지시

1. 위 프로필을 아래 형식으로 하나씩 출력한다. 프로필 사이는 빈 줄 하나로 띄운다.

   [ {icon 이모지} {name} ]
    - {provider} {model} [ {thinkingOptionId} ]
    - {notes}

   `{model}`이 `{provider}`로 시작하면 `{provider}`를 붙이지 않고 `{model}`만 쓴다.
   (claude + claude-sonnet-5 → claude-sonnet-5, codex + gpt-5.6-luna → codex gpt-5.6-luna)
   `icon`은 아래 매핑으로 이모지로 바꿔 쓴다. 매핑에 없으면 🔹를 쓴다.
   {이번 페이로드에 쓰인 아이콘만 골라 한 줄로: compass=🧭 search=🔍 ...}

2. 이 PC에서 그 provider·model을 실제로 쓸 수 있는지 확인한다. Paseo MCP가 붙어 있으면
   list_models로 확인하고, 없으면 앱에서 확인해 달라고 사용자에게 요청한다. 쓸 수 없는
   것은 그 프로필을 짚어 알린다.

3. 그다음 사용자에게 묻는다 — "이 N개를 그대로 등록할까요, 아니면 수정하고 싶은 프로필이
   있나요?" 물을 때 위 「특이사항」을 함께 보여준다. 답을 받기 전에는 설정 파일을 고치지
   않는다.

4. 답을 받은 뒤 다음 스텝으로 진행한다.
   - 그대로 → 전체를 등록한다.
   - 수정 → 어느 프로필의 어느 필드를 어떻게 바꿀지 받아 반영한 뒤 등록한다.
   - 일부만 → 등록할 프로필만 골라 받는다.

5. 등록은 `~/.paseo/config.json` 의 `daemon.agentProfiles` 배열에 위 객체를 추가하는
   것이다. `id`가 이미 있으면 덮어쓸지 사용자에게 묻는다.

6. 등록을 마치면 Paseo 데몬을 재시작해야 새 프로필이 앱에 보인다는 것을 알리고, 지금
   재시작할지 사용자에게 묻는다. 답을 받기 전에 재시작하지 않는다.
````
