# 브레인스토밍

진입 판정은 SKILL.md 「브레인스토밍 진입」에 있다. 사용자가 브레인스토밍·아이디어를 명시적으로 요청하면 바로 이 문서로 온다.

## 진행

- **팀장이 직접 대화 상대다.** 아이디어를 내는 일 자체를 워커에 맡기지 않는다.
- 사실 확인·코드베이스 조사·선례 조사가 필요하면 **그 조사만** 워커에 맡긴다. 프로필은 `references/delegation.md` 「프로필 선택과 값 이관」의
  역할↔프로필 해석으로 고르고, 결과는 같은 문서 「결과 파일로 받는다」대로 결과 파일로 받는다. 브레인스토밍 대화에는
  판단에 필요한 만큼만 옮기고 결과 파일 본문을 통째로 옮기지 않는다.
- 조사 워커를 띄웠으면 SKILL.md 「기동 보고」를 낸다. 브레인스토밍 중이라는 이유로 생략하지 않는다.
  그 조사는 그 자체로 하나의 레벨 판정 대상이며 실행 디렉터리는 제 것을 쓰고, 레벨 2로 판정된 경우에만 자체 `GRAPH.md`를 쓴다 —
  아래 `BRAINSTORMING.md`의 디렉터리와 섞지 않는다.
- 사용자가 고른 것만 확정이다. 아직 고르지 않은 아이디어를 확정 사항처럼 다루지 않는다.

## 끊는 시점

아래 셋 중 하나에 걸리면 끊고 게이트로 간다.

1. 만들 것 또는 풀 방향이 하나로 좁혀졌다.
2. 남은 선택지가 지금 있는 정보로는 더 좁혀지지 않는다 — 그 사실과 남은 선택지를 그대로 적는다.
3. 사용자가 그만하자고 했다.

## `BRAINSTORMING.md`

- 경로는 `references/delegation.md` 「결과 파일로 받는다」의 실행 디렉터리 `.skywork/paseo-orchestration/{YYYY-MM-DD}-{슬러그}/` 바로 아래
  `BRAINSTORMING.md`다. 이 시점에 그 디렉터리를 정하고, 아래 게이트를 통과해 짜는 레벨 2 그래프는
  **같은 디렉터리**에 Python으로 실행하는 `scripts/graph_update.py create`로 `GRAPH.md`를 쓴다. 경로 인수는 [references/delegation.md](delegation.md) 첫머리의 워크스페이스 `cwd` 기준 절대 경로를 쓴다.
- 내용이 이 세션 대화뿐이므로 **팀장이 직접 쓴다**(SKILL.md 「리더가 직접 하는 일」).
- 노드 산출물이 아니다. 노드 ID를 붙이지 않고, 레벨 2 `GRAPH.md` 노드 표에 행을 만들지 않으며,
  실패 보고 경로도 두지 않는다.
- 담는 것 — 풀려는 문제 / 나온 아이디어와 각각의 장단 / 사용자가 고른 방향 / 버린 선택지와
  버린 이유 / 아직 답이 없는 질문.
- 담지 않는 것 — 확정되지 않은 것을 확정으로 적는 것, 스펙·수용 기준·구현 방법. 그것은
  스펙 작성 역할의 몫이다.

## 워크플로우 진입 게이트

`BRAINSTORMING.md`를 쓴 뒤 구현·워크플로우 실행까지 요청받았으면 그 범위의 그래프를 짜고
`references/level2.md` 「계획 승인」의 실행 전 계획 승인 1회로 진행한다. 아이디어만 요청받았으면 정리 결과를 보고하고 끝낸다.

- **실행을 요청받았으면 `references/level2.md`로 간다.** 그래프는 **스펙 작성 노드부터** 시작하고 `BRAINSTORMING.md` 경로가
  그 노드의 입력이다. 이 경로는 스펙 작성의 출력이 다음 단계의 입력이어서 `references/delegation.md` 「레벨 판정 게이트」 Step 1에 걸리므로
  레벨 2다. 워크플로우 진입 동의와 계획 승인을 따로 받지 않고 같은 실행 범위의 계획 승인 1회로 합친다.
- **승인 뒤에 갈 곳은 그 그래프뿐이다.** 구현 워커를 먼저 띄우거나 스펙 작성을 건너뛰고 다른
  단계부터 시작하지 않는다. 사용자가 다른 것을 지시하면 그 지시가 이긴다.
- **계획 승인을 거절하면 거절 사실만 보고하고 멈춘다.** 워커를 기동하지 않는다.
- 무응답·주제 전환은 승인이 아니다.
