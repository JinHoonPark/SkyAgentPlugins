# 브레인스토밍

진입 판정과 진입 물음은 SKILL.md 10절에 있다. 사용자가 그 물음에 동의한 뒤 이 문서로 온다.

## 진행

- **팀장이 직접 대화 상대다.** 아이디어를 내는 일 자체를 워커에 맡기지 않는다.
- 사실 확인·코드베이스 조사·선례 조사가 필요하면 **그 조사만** 워커에 맡긴다. 프로필은 4절
  역할↔프로필 해석으로 고르고, 결과는 5절대로 결과 파일로 받는다. 브레인스토밍 대화에는
  판단에 필요한 만큼만 옮기고 결과 파일 본문을 통째로 옮기지 않는다.
- 조사 워커를 띄웠으면 7절 기동 보고를 낸다. 브레인스토밍 중이라는 이유로 생략하지 않는다.
  그 조사는 그 자체로 하나의 레벨 판정 대상이고 실행 디렉터리와 `GRAPH.md`도 제 것을 쓴다 —
  아래 `BRAINSTORMING.md`의 디렉터리와 섞지 않는다.
- 사용자가 고른 것만 확정이다. 아직 고르지 않은 아이디어를 확정 사항처럼 다루지 않는다.

## 끊는 시점

아래 셋 중 하나에 걸리면 끊고 게이트로 간다.

1. 만들 것 또는 풀 방향이 하나로 좁혀졌다.
2. 남은 선택지가 지금 있는 정보로는 더 좁혀지지 않는다 — 그 사실과 남은 선택지를 그대로 적는다.
3. 사용자가 그만하자고 했다.

## `BRAINSTORMING.md`

`python3`가 없으면 Python 명령을 `python`으로 실행한다.

- 경로는 5절의 실행 디렉터리 `.skywork/paseo-orchestration/{YYYY-MM-DD}-{슬러그}/` 바로 아래
  `BRAINSTORMING.md`다. 이 시점에 그 디렉터리를 정하고, 아래 게이트를 통과해 짜는 그래프는
  **같은 디렉터리**에 `python3 scripts/graph_update.py create`로 `GRAPH.md`를 쓴다.
- 내용이 이 세션 대화뿐이므로 **팀장이 직접 쓴다**(SKILL.md 「리더가 직접 하는 일」).
- 노드 산출물이 아니다. 노드 ID를 붙이지 않고, `GRAPH.md` 노드 표에 행을 만들지 않으며,
  실패 보고 경로도 두지 않는다.
- 담는 것 — 풀려는 문제 / 나온 아이디어와 각각의 장단 / 사용자가 고른 방향 / 버린 선택지와
  버린 이유 / 아직 답이 없는 질문.
- 담지 않는 것 — 확정되지 않은 것을 확정으로 적는 것, 스펙·수용 기준·구현 방법. 그것은
  스펙 작성 역할의 몫이다.

## 워크플로우 진입 게이트

`BRAINSTORMING.md`를 쓴 뒤 **"스펙 작성부터 워크플로우를 실행해볼까요?"**를 묻고 턴을 마쳐
사용자 답을 기다린다. 화면에 필요한 내용이 현재 컨텍스트에 없으면 [references/FORM.md](FORM.md)의 `## 브레인스토밍 게이트`만 읽는다. 그 형식을 따른다.

- **승인하면 9절로 간다.** 그래프는 **스펙 작성 노드부터** 시작하고 `BRAINSTORMING.md` 경로가
  그 노드의 입력이다. 이 경로는 스펙 작성과 그 확정 게이트가 들어가 2절 Step 1에 걸리므로
  레벨 2다. 계획 승인은 9절의 승인 화면으로 따로 받는다 — 이 게이트의 승인이 그 승인을
  대신하지 않는다.
- **승인 뒤에 갈 곳은 그 그래프뿐이다.** 구현 워커를 먼저 띄우거나 스펙 작성을 건너뛰고 다른
  단계부터 시작하지 않는다. 사용자가 다른 것을 지시하면 그 지시가 이긴다.
- **거절하면 `BRAINSTORMING.md`만 남기고 멈춘다.** 그래프를 짜지 않고 `GRAPH.md`도 만들지 않는다.
- 무응답·주제 전환은 승인이 아니다.
