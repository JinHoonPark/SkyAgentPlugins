# 실패·재시도·재개

노드가 실패했거나, 재시도·프로바이더 장애·권한 대기·사용자 중단·레벨 2 재개를 판정할 때
읽는다. 6절 표가 게이트이고, 이 문서가 동작이다.

이 문서와 현재 호스트 정책이 어긋나면 **호스트 정책을 따른다.** 스킬 절차로 권한을 올리거나
실행 중 메시지를 강제하거나 전역 config를 고쳐 우회하지 않는다. 막히면 그 사실을 보고한다.

종료(에이전트가 멈춤)와 합격 기준 통과는 다르다. 멈춘 것만으로 `완료`로 쓰지 않는다.

## 실패 보고 우선

완료 판정은 이 순서다. 앞이 뒤보다 이긴다.

1. 실패 보고 경로에 내용이 있으면 `실패`다. 결과 파일이 있어도, 에이전트가 정상 종료여도
   통과로 뒤집지 않는다.
2. 결과 파일 경로의 파일과 그 노드의 합격 기준 한 줄을 대조해 맞으면 `완료`.
3. 결과 파일은 있으나 합격 기준과 맞지 않으면 `실패`다. 자동 재시도하지 않고, 의존 노드는
   기동하지 않는다.
4. 에이전트는 끝났는데 실패 보고도 결과 파일도 없으면 원인을 특정하지 못한 실패로 보고하고
   재시도하지 않는다.

## 의존 차단

스테이지 경계에서 판정한다. `실패` 노드에 의존하는 노드는 `create_agent`를 호출하지 않고
상태를 `대기`로 남겨 보고에 `미기동`으로 낸다. 의존하지 않는 같은 스테이지 노드는 3절
큐로 계속 돌린다.

부분 실패 보고: 노드별 상태(`완료`/`실패`/`미기동`) + 완료된 결과 파일 경로 + 무엇을 못 했는지.

## 이미 받은 승인

같은 요청·같은 범위에서 이미 받은 계획 승인, 되돌리기 어려운 작업의 승인, 워커 권한 `allow`는 다시 묻지
않고 재사용한다. 그래프 형태가 그대로인 재개에도 새 계획 승인은 없다. 범위가 바뀌면 9절·
6절 게이트로 다시 받는다.

## 권한

- **대기** — 기존 승인 범위 안이면 다시 묻지 않고 재사용해 응답한다. 없거나 범위를 넘는
  요청만 원문 그대로 보여주고 사용자 결정을 받는다. 자동 승인하지 않는다.
- **명시 거부** — 재시도하지 않는다. `full-access`나 `sessionMode`로 우회하지 않는다.
  그 노드를 `실패`로 두고 보고한다.

부수효과가 없다는 이유만으로 거부를 재시도 가능으로 분류하지 않는다.

## 재시도

자동 재시도는 아래 두 조건을 **모두** 만족할 때만, **1회만** 한다. 무조건 재시도하지 않는다.
레벨 2는 노드 표 `재시도` 셀에 `가능 · 한도 1 · 사용 N` 또는 `불가`를 적는다. 열을 늘리지
않는다.

**호출 전에 횟수를 기록한다.** 사용 횟수를 셀·`GRAPH.md`(레벨 2) 또는 작업 상태(레벨 1)에
반영한 뒤에만 `create_agent`를 다시 부른다. 호출 뒤에 적으면 기록이 비기 전에 한 번 더
호출된다.

**조건 1 — 워커가 작업 부수효과를 남기기 전에 죽었는가.**

| 재시도 가능 (자동 1회) | 재시도 금지 (보고하고 사용자 판단) |
| --- | --- |
| 기동 실패 — 프로세스·셸 생성 실패. **에이전트 미생성이 조회로 확인됐거나, 엔티티는 있으나 프로세스·셸 부수효과가 0임이 확인된 경우만** — 엔티티 상태를 기록하고 허용 횟수 안에서 재시도한다 | 워커가 작업을 시작한 뒤의 실패 (부분 실행) |
| 도구 인수 검증 실패 (리더가 인수를 고쳐 재호출). 생성 호출이 거절된 것이 응답으로 확인된 경우 | 합격 기준을 못 맞춘 실패 (같은 브리핑이면 같이 실패) |
| | 브리핑 결함으로 인한 실패 |
| | 원인을 특정하지 못한 실패 |
| | 권한 **명시 거부** |
| | 생성 결과가 **불명**인 전송·타임아웃 — 아래 「불명 생성」 |

**조건 2 — 그 노드가 멱등한가.** 설계 때 `재시도` 셀에 미리 적는다. 아래를 **전부**
만족할 때만 멱등이다.

- 결과 파일이 지정된 경로에 대한 쓰기·덮어쓰기뿐이다.
- git 커밋·푸시·태그·브랜치 조작을 하지 않는다.
- 외부 전송(메일·메신저·API POST·업로드)을 하지 않는다.
- 파일·디렉터리 삭제와 이름 변경을 하지 않는다.
- 저장소 밖 설정을 고치지 않는다.

하나라도 어기면 `불가`다. 실패하면 자동 재시도 없이 현재 상태와 무엇까지 실행됐는지를
먼저 보고한다.

부분 실행 여부는 셋을 함께 본다 — 결과 파일의 존재와 내용, 실패 보고 경로, `git status`의
작업 트리 변화. 하나라도 작업이 시작됐음을 보이면 재시도하지 않는다. 실패 보고가 있으면
이 항보다 「실패 보고 우선」이 이긴다.

기동이 실패해 활성 슬롯을 잡지 못했으면 그 작업은 슬롯을 점유하지 않은 것으로 본다.
브리핑 결함은 재시도하지 않는다.

`재시도: 불가`로 표시된 노드가 실패하면 `create_agent` 재호출은 0회다.

## 불명 생성 — 중복 기동 금지

`create_agent` 호출이 타임아웃·전송 실패·응답 유실로 끝났고 `agentId`를 못 받았으면
**기동 실패로 단정하지 않는다.** 다시 띄우기 전에 조회한다.

1. 이 노드 행에 이미 `agentId`가 있으면 그 ID로 상태를 본다.
2. 없으면 부모 라벨·방금 쓴 `title`/`labels`로 실제 에이전트를 찾는다.
3. 에이전트가 있으면 그 `agentId`를 기록하고 중복 `create_agent`를 호출하지 않는다.
   실행 중이면 그대로 두고, 이미 끝났으면 「실패 보고 우선」으로 판정한다.
4. 조회가 부모 라벨과 노드 식별로 특정 에이전트를 확인했는데 결과가 비어 있어야 비로소
   기동 실패다. 그때만 위 「재시도」가 적용된다. 조회 자체가 실패했거나, 권한이 없어
   조회를 못 했거나, 여러 후보가 나와 특정하지 못하면 미생성 확인이 아니다. 다시
   띄우지 않는다.

전송 실패를 자동 1회 재시도 대상으로 두지 않는 이유가 이것이다 — 생성이 이미 됐을 수
있다.

## 실행 중 ID

노드 행에 `agentId`가 있으면 그 ID로 `get_agent_status`(또는 이 호스트에서 동등한 조회)를
부른다. 실행 중이거나 이미 합격 기준을 통과한 노드를 완료 재기동하지 않는다. ID를 버리고 그래프를
처음부터 다시 돌리지 않는다.

## 주입

실행 중인 워커에 지시를 보내는 수단은 `send_agent_prompt`다. 폐기할 때만 `cancel_agent`다.
**호스트가 실행 중 메시지 또는 모드 변경을 막으면 보내지 않고 보고한다.**

- 조회형·범위 내 명확화는 승인 없이 보낸다. 이미 쓴 결과 파일을 덮어쓸지·이어 쓸지·버릴지를
  주입 프롬프트에 명시한다.
- 범위 변경(합격 기준 변경·추가, 대상 파일 추가, 역할 변경, 노드 추가·삭제, 되돌리기 어려운 작업 추가,
  권한을 올리는 모드 변경)은 **보내기 전에** 승인을 받는다. 승인 없이 종료하면 호출하지
  않고 `GRAPH.md`도 바꾸지 않는다.
- 레벨 2에서 범위 변경을 승인받으면 보낸 뒤 해당 노드 행을 `GRAPH.md`에 반영한다.
- 재설계(그래프 형태 변경, 토론 라운드 추가)는 9절의 계획 승인을 다시 받는다.
- 애매하면 범위 변경으로 본다.

사용자가 실행을 중단할 때 실행 중 전 노드를 중단하고, `GRAPH.md`를 그 시점 상태로 즉시 갱신한 뒤 노드별
상태와 남은 결과 파일 경로를 보고한다(9절 GRAPH.md).

## codex 셸 생성 실패

codex 워커의 실제 모드는 요청값과 다를 수 있고, 그 상태에서 `CreateProcessAsUserW` 오류로
셸이 뜨지 않은 사례가 있다. 상시 위험으로 관찰한다.

셸이 필요한 노드에 codex 프로필을 배정하면 `create_agent` **응답의** `currentModeId`를 그
자리에서 읽는다. 호출 응답에서 이미 오므로 별도 조회를 기다리지 않는다.

**`full-access`로 자동 승격하지 않는다.** 모드를 올리는 것은 권한 변경이다.

- 이 호스트가 그 모드를 막으면 바꾸지 않고 실패로 보고한다.
- 사용자가 그 노드에 이미 준 권한이 그 모드를 덮으면 재사용한다.
- 그 외에는 승인을 받은 뒤에만 `settings.modeId` 또는 호스트가 허용하는 `sessionMode`로
  바꾼다. 실행 중 메시지 자체가 호스트에 막혀 있으면 `send_agent_prompt`로 우회하지 않는다.
- 같은 값으로 재시도하지 않는다. 재기동이 허용된 경우에만 위 「재시도」한도 1회에 센다.
  횟수는 호출 전에 기록한다.

Codex라고 해서 특정 모드를 미리 강제하지 않는다.

## 프로바이더 장애

워커 하나 실패로만 다루면 활성·대기 큐가 같은 provider로 순차 투입되며 각자 재시도를
소진한다. **둘을 모두** 만족하면 노드 실패가 아니라 프로바이더 장애다.

- 같은 provider에서 **서로 다른** 노드가 연속 2건, 기동 단계에서 실패했다. 1건은 노드
  실패다.
- 오류가 provider 범위다. 인증·한도(세션/사용량 한도, `401`, `403`), 엔드포인트(`404`,
  `5xx`, 프로바이더 API 호스트 연결 실패), 요청 내용과 무관한 반복(문구가 같고 요청
  식별자만 바뀜) 셋 중 하나다.

`CreateProcessAsUserW` 같은 로컬 프로세스 실패는 provider 범위가 아니다. 위 셸 실패다.
존재하지 않는 `provider/model` 같은 인수 오류는 세 분류 어디에도 넣지 않는다.

판정하면 순서대로 한다.

1. 막힌 provider로 갈 예정이던 대기 작업을 새로 기동하지 않는다. 다른 provider 대기는
   계속 투입한다.
2. 실행 중 워커는 중단하지 않고 결과를 받는다.
3. 보고한다 — provider 이름 / 오류 원문 한 줄 / 연속 실패한 노드 ID 2건 / 못 쓰게 된
   프로필 이름 / 대기 큐에 남은 작업 수.
4. 대체는 자동으로 하지 않는다. 승인을 받는다. 제시할 것 넷 — (a) 막힌 프로필 이름과
   그 `notes`, (b) 대체 후보 프로필 이름과 그 `provider/model`·`notes`, (c) 두 `notes`가
   어떻게 다르고 무엇이 달라지는지, (d) 대체하지 않고 장애 해소를 기다리는 선택지.

살아 있는 provider의 프로필이 하나도 없으면 대체를 제안하지 않고 멈춘다. 실행 중 결과만
받고, 완료된 결과 파일 경로와 미기동 목록을 보고한다. 리더가 워커 대신 작업을 수행하지 않는다.

승인한 대체는 노드 표의 프로필 열을 바꾼 것이므로 `GRAPH.md`를 갱신한 뒤 재개한다.
새 계획 승인은 그 대체 승인으로 충분하다.

## 재개

같은 요청의 중단·압축 복구에 쓴다. 새 요청의 그래프를 재사용하는 경로가 아니다.

1. `list_agents`로 자식 에이전트를 조회한다. Paseo가 자식의 `labels`에
   `paseo.parent-agent-id`를 넣으므로 이것으로 식별한다. 무엇이 이미 떠 있는지 확인한
   뒤에 설계로 돌아갈지 판단한다.
2. 실행 디렉터리의 `GRAPH.md`가 있으면 읽는다. 기록 파일이 없고 자식도 없으면 재개가
   아니라 9절 설계다.
3. `agentId`가 있는 행마다(또는 조회된 자식마다) 먼저 실제 에이전트가 실행 중인지
   조회한다. **실행 중이면** 실패 보고 경로에 내용이 있어도 중복 기동하지 않고 상태를
   `실행 중`으로 맞춘 채 종료를 기다린다. `완료`이거나 실행 중인 노드는 다시 띄우지
   않는다.
4. 종료가 확인된 뒤에 결과 파일 경로와 **실패 보고 경로**를 대조해 「실패 보고 우선」 순서로
   판정한다.
5. `GRAPH.md`가 `완료`로 기록돼 있다는 것만으로 완료 처리하지 않는다. 위 조회·대조 결과가
   그 기록과 다르면 재실행하지 않고 불일치를 보고한 뒤 그 노드에 의존하는 노드는
   기동하지 않는다.
6. `대기`는 기동한다. `실패` 노드는 재시도 조건과 잔여 횟수를 충족할 때만 재기동한다.
   한도를 이미 썼으면 기동하지 않고 보고한다. 명시 거부된 노드는 기동하지 않는다.
7. 스테이지를 반만 채운 채 다음으로 넘기지 않는다. 중단된 스테이지를 채워 전원이 합격 기준을
   통과한 뒤에만 다음 스테이지로 간다.
8. 그래프 형태가 그대로면 이미 받은 계획 승인을 재사용한다.

기록이 실행 중인데 에이전트가 없고 합격 기준을 통과한 결과 파일도 없으면 「불명 생성」으로 조회한 뒤
`실패` 또는 확인된 미생성으로 맞춘다. 추측으로 완료 재기동하지 않는다.
