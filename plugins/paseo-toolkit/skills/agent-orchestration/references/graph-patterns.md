# 그래프 패턴

레벨 2 그래프를 **설계할 때** 읽는다. 완성된 그래프를 저장·재사용하지 않는다. 요청마다
9절의 노드 표로 새로 짠다. 실행 모델은 하나다 — 스테이지를 통째로 기동하고, 그 스테이지
전원이 **수용 조건까지 통과**한 뒤에만 다음으로 간다.

## 표기

스테이지는 `>>`, 같은 스테이지의 병렬은 `|`. 토론 라운드 수도 이 표기에 스테이지로
드러나게 둔다. 전역 라운드 상한은 없다.

```text
1. 조사
   >> 2-1. 분석A | 2-2. 분석B | 2-3. 분석C
   >> 3. 취합
   >> 4-1. 토론자1 | 4-2. 토론자2 | 4-3. 토론자3
   >> 5. 결론
```

한 스테이지 노드 수가 활성 상한 10을 넘으면 3절 큐(활성 10 + FIFO)를 **그 스테이지
안에서** 쓴다. 대기 노드가 남아 있으면 그 스테이지는 끝나지 않는다.

## 순차

입력이 앞 노드 산출물일 때. 노드를 한 스테이지에 하나씩 둔다.

```text
1. 초안 >> 2. 확장 >> 3. 정리
```

같은 파일을 둘 이상이 쓰면 이 형태로 **고친다.** 워크스페이스를 나눠 우회하지 않는다.
격리는 병합을 새로 만들고, 뒤 노드가 앞 파일을 못 읽는다. worktree는 사용자가 명시할
때만 쓰고, 그때 각 worktree의 실제 경로를 팬인 노드 입력에 넣는다.

## 팬아웃

같은 입력을 서로 다른 대상·관점으로 나눌 때. 한 스테이지에 `|`로 둔다.

```text
1. 범위 확정
   >> 2-1. 모듈A | 2-2. 모듈B | 2-3. 모듈C
```

병렬 노드의 산출물 경로는 서로 달라야 한다. 경로가 겹치면 순차로 고친다.

## 팬인

여러 산출물을 한 노드가 모을 때. 앞 스테이지 전원 수용 통과 뒤에 둔다.

```text
2-1. 분석A | 2-2. 분석B | 2-3. 분석C
   >> 3. 취합
```

취합 브리핑에는 앞 노드 산출물의 **경로만** 넣는다. 본문을 붙이지 않는다.

## 역할 분화

같은 대상에 구현과 검토처럼 역할이 갈릴 때. 검토는 구현 산출물이 있어야 하므로 보통
다음 스테이지다. 프로필은 서로 달라야 하고, 검토 브리핑은 9절을 따른다. 구현 보고서
텍스트는 넣지 않는다.

```text
1. 구현
   >> 2. 검토
```

구현이 여러 파일이면 팬아웃 뒤에 검토를 팬인하거나, 파일마다 검토를 같은 스테이지에
병렬로 둔다. 검토끼리 같은 파일을 쓰면 순차로 고친다.

## 토론

서로 다른 입장 노드를 한 스테이지에 두고, 다음 스테이지에서 사회·결론이 경로만 읽는다.
라운드를 더 돌리려면 스테이지를 늘리는 재설계다. 승인 없이 라운드를 추가하지 않는다.

지정한 라운드를 다 썼는데 수렴하지 않으면 **결론을 지어내지 않는다.** 남은 쟁점과 각
토론자의 마지막 입장 경로를 취합해 보고하고, 더 돌지는 사용자 판단으로 올린다.

## 5스테이지 예시

조사 → 분석 3 → 취합 → 토론 3 → 결론. 승인 전에 워커를 띄우지 않는다.

```text
1. 조사
   >> 2-1. 분석A | 2-2. 분석B | 2-3. 분석C
   >> 3. 취합
   >> 4-1. 토론자1 | 4-2. 토론자2 | 4-3. 토론자3
   >> 5. 결론
```

- 스테이지 1 입력은 리더 브리핑. 이후 입력은 앞 산출물 경로.
- 분석 3은 대상이 겹치지 않게 나눈다. 같은 파일 쓰기면 2-1 >> 2-2 >> 2-3으로 고친다.
- 결론 노드는 토론 산출물 경로만 받는다. 수렴 실패 시 5를 「결론 작성」이 아니라
  「쟁점 보고」수용 조건으로 두었는지 설계 때 밝힌다.
