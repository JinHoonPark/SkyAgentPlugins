# 그래프 패턴

레벨 2 그래프를 **설계할 때** 읽는다. 완성된 그래프를 저장·재사용하지 않는다. 요청마다
9절의 노드 표로 새로 짠다. 실행 모델은 하나다 — 스테이지를 통째로 기동하고, **선택된 경로의
활성 노드가 통과하고 필요한 사용자 게이트가 확정되면** 다음으로 간다. `생략`은 차단 원인이
아니다.

## 표기

표기는 9절의 `flowchart TD` mermaid와 `N1` 형식이다. 토론 라운드 수도 다이어그램에
스테이지로 드러나게 둔다. 기본 총 3라운드이고, 연장은 횟수와 대상을 지정한 **사용자
결정**으로만 한다.

노드와 스테이지는 **역할 이름**으로 기술한다. 프로필 id는 실제 선택 결과와 프리셋 예시에만 쓴다.

관계선은 한 줄에 하나씩 쓴다. 전달물·조건·반복 한도는 노드 설명이 아니라 관계선 라벨에
둔다 — `N1 -->|통과| N2`처럼 쓴다.

되돌아가는 피드백 엣지는 `피드백:`으로 시작한다 —
`N6 -->|피드백: 수정 필요, 잔여 2회| N1`.

노드 라벨도 9절과 같다 — 워커 노드는 `[ 노드ID · 역할 ]<br/>모델명<br/>작업 한 마디` 세
줄, 공동 판정·사용자 게이트 같은 제어 노드는 `[ 노드ID · 종류 ]<br/>판단 대상 또는 확정
대상` 두 줄이고, 제어 노드에는 모델명과 `agentId`를 두지 않는다.

한 스테이지 노드 수가 활성 상한 10을 넘으면 3절 큐(활성 10 + FIFO)를 **그 스테이지
안에서** 쓴다. 대기 노드가 남아 있으면 그 스테이지는 끝나지 않는다.

## 순차

입력이 앞 노드 결과 파일일 때. 노드를 한 스테이지에 하나씩 두고 `N1 -->|전달| N2`와
`N2 -->|전달| N3` 두 줄로 잇는다.

같은 파일을 둘 이상이 쓰면 순차로 고친다. 워크스페이스를 나눠 우회하지 않는다. worktree는 사용자가 명시할 때만 쓰고, 그때 각 worktree의 실제 경로를 팬인 노드 입력에 넣는다.

## 팬아웃

같은 입력을 서로 다른 대상·관점으로 나눌 때. 같은 앞 노드에서 N2·N3·N4가 갈라
나오게 그린다.

병렬 노드의 결과 파일 경로는 서로 달라야 한다. 경로가 겹치면 순차로 고친다.

## 팬인

여러 결과 파일을 한 노드가 모을 때. 선택된 경로의 활성 노드가 통과하고 필요한 사용자 게이트가
확정된 뒤에 팬인한다. `생략`은 차단 원인이 아니다. N2·N3·N4가 N5(비교 분석)로 모이게 그린다.

비교 분석 브리핑에는 앞 노드 결과 파일의 **경로만** 넣는다. 본문을 붙이지 않는다.

## 역할 분화

같은 대상에 구현과 검토처럼 역할이 갈릴 때. 검토는 구현 결과 파일이 있어야 하므로 보통
다음 스테이지다. 검토 노드는 5절의 세 조건을 따른다 — 작성 워커와 다른 `agentId`,
작성자의 대화·보고를 입력으로 받지 않음, 선택한 프로필의 `notes`가 검토를 허용함. 전용 검토
프로필이 있으면 우선한다. 검토 브리핑은 5절을 따르고 구현 보고서 텍스트는 넣지 않는다.
표기는 9절의 표기 규칙과 같다.

구현이 여러 파일이면 팬아웃 뒤에 검토를 팬인하거나, 파일마다 검토를 같은 스테이지에
병렬로 둔다. 검토끼리 같은 파일을 쓰면 순차로 고친다.

## 토론

서로 다른 입장 노드를 한 스테이지에 두고, 다음 스테이지에서 사회·결론이 경로만 읽는다.
라운드를 더 돌리려면 스테이지를 늘리는 재설계이고, 기본 총 3라운드를 넘기는 연장은 횟수와
대상을 지정한 **사용자 결정**으로만 한다. 승인 없이 라운드를 추가하지 않는다.

지정한 라운드를 다 썼는데 수렴하지 않으면 **결론을 지어내지 않는다.** 남은 쟁점과 각
토론자의 마지막 입장 경로를 취합해 보고하고, 더 돌지는 사용자 판단으로 올린다.

토론 결과를 받는 노드는 수렴 실패 시 합격 기준을 「결론 작성」이 아닌 「쟁점 보고」로 두었는지 설계 때 밝힌다.
