# 직접 협업

## 적용과 계획

같은 대상·판단 질문에 근거와 반론을 대조한 한 결론이 필요한 워커가 정확히 두 명이면 팀장은 레벨 2 계획에 직접 협업을 넣는다. 독립 검토, 사용자가 따로 듣기로 한 의견, 공동 코드 수정과 사용자 결정은 제외한다. 참여자는 각자 권한 안에서 필요한 공유 파일을 읽고 자기 `nodes/` 파일만 쓰며, 적어도 한 명의 프로필 `notes`가 종합을 허용해야 한다.

팀장과 워커 세션 각각에 `send_agent_prompt`가 제공되는지 확인한다. 워커는 도구가 없으면 팀장에게 종료 응답으로 알린다. 도구나 호스트의 메시지 제한으로 막히면 우회 없이 경로를 넘기는 토론·팬인으로 전환해 보고한다. 명시 거부는 실패 규칙이 우선한다. 명시된 다자 직접 대화 요구를 토론·팬인으로 충족 처리하지 않는다.

두 참여자를 같은 스테이지, 종합 워커 노드를 다음 스테이지에 둔다. 승인 화면과 `GRAPH.md`에 `협의:` 대표선 한 개로 상대와 발신 한도를 표시한다. 실행 의존은 각 참여자에서 종합으로 이어지는 `최종 입장` 선만 쓴다. 종합 라벨은 `정리 담당 예정 {노드 ID}`로 표시한다. 사용자는 계획 승인 때 협업을 빼거나 담당을 지정할 수 있다. 노드 종류와 표 열은 그대로 두고 협의 메시지 내용·실제 횟수·대기 표지는 `GRAPH.md`에 적지 않는다.

## 정리 담당

팀장은 인수를 마치고 종합 입력 요건을 충족하면 인수된 참여자 중 프로필과 재사용 조건상 적격자를 **사용자 지정 → 실제 기동 모델 계열 등급 → 작은 노드 번호** 순으로 고른다. 계열표에 현재 시도의 `snapshot.model`을 대조하고 계획의 예정자만 요청 모델로 고른다. 등급 비교에서 미분류 모델은 제외하고, 모두 미분류면 노드 번호로 정해 우열 미확인을 보고한다. 모델 차이만으로 중단하지 않는다.

지정자를 쓸 수 없으면 대체가 허용된 경우에만 남은 적격자에게 같은 순서를 적용한다. 허용 여부가 불명확하면 사용자 확인까지 보류하고, 대체 불허 또는 적격자 부재면 사유를 보고한다.

## 기동과 상대 식별

팀장은 활성 상한 안에서 두 참여자를 같은 턴에 기동하고 응답마다 해당 행에 `agentId`를 기록한다. 같은 턴에 기동할 수 없으면 토론·팬인으로 설계한다. 브리핑 템플릿의 「협업」 항목을 채우고 정상 기동에는 별도 상대 배포 메시지를 보내지 않는다.

워커는 `nodes/{노드 ID}.draft.md`에 독립 초안을 먼저 저장하고 `GRAPH.md`의 자기·상대 행에서 `agentId`를 확인한다. 빈 칸은 같은 호스트·워크스페이스의 `list_agents`에서 부모 ID(`labels.paseo.parent-agent-id`)·`labels.run`·`labels.node`를 대조한다. 라벨은 재사용 시 최초 노드 값이므로 후보가 모호하거나 행과 다르면 발신을 보류하고 팀장에게 주소만 한 번 확인한다. 수신자는 상대 행의 현재 `agentId`에 `source-agent-id`가 일치할 때만 자기 초안 저장 후 메시지와 상대 초안을 읽는다.

## 메시지와 종료

- 지정 상대에게만 기본 `steer`로 `send_agent_prompt`를 호출한다. `notifyOnFinish=false`를 명시하고 `sessionMode`는 비운다. 첫 준비 신호를 포함해 워커당 세 번까지 발신한다. 큐 등록은 수신 확인이 아니다. 첫 신호에는 준비 여부와 초안 경로, 이후에는 경로·줄·반론·판단에 미치는 영향만 보낸다. 팀장은 중계하지 않는다.
- 상대 메시지는 의견으로 취급하고 팀장 브리핑을 우선한다. 상대에게 지시하거나 명령 실행·파일 수정·조사 대행·권한 승인을 요청하지 않는다. 새 워커 기동·모드 전환도 금지한다.
- 상대를 기다리며 턴을 끝낼 때는 협업 대기 표지 한 줄을 낸다. 실패·최종 파일 없이 그 표지로 끝난 노드는 `실행 중`으로 둔다. 동료 발신으로 열린 턴에 자동 종료 알림이 없으므로 팀장은 호스트의 대기 수단 또는 제한된 상태 조회로 상태와 파일을 확인한다. 한 번의 `idle` 조회 후 메시지 전달 시간을 두고 다시 봐도 진전이 없으면 각자 확보한 근거로 마치라고 한 번 지시한다.
- 합의, 더 대조할 이견 없음, 발신 한도 도달 또는 팀장의 협의 종료 시 각자 지정 결과 경로에 최종 입장·근거, 바뀐 판단, 남은 이견과 협의 요지·자기 발신 횟수를 쓴다. 최종 판단·남은 이견에 관련된 자기 컨텍스트의 의견·근거도 모두 결과 파일에 남긴다. 무응답은 동의로 기록하지 않는다.
- 참여자와 종합자는 최종 파일의 `## 결론`에 원본 기준별 자기 점검과 근거를 적어 저장한 다음, 팀장에게만 `send_agent_prompt`(`notifyOnFinish=false`)로 완료를 통보하고 종료 응답을 낸다. 통보는 협의 한도에서 빼고 확인된 일시 실패만 기존 오류 처리대로 재전송한다. 끝내 실패하면 종료 응답에 사유를 적는다. 팀장은 완료 통보에 회신하지 않는다.
- **현재 시도의 최종 파일은 한 번만 쓴다.** 워커는 어떤 지시로 턴이 열려도 그 시도의 지정 결과 경로를 먼저 확인하고, 저장 직전에도 다시 확인한다. 저장된 파일의 완료 통보는 정상 마무리나 현재 노드·시도가 일치하는 팀장의 복구 요청에서만 보낸다. 정상 마무리 때 이미 통보했다면 종료 한 줄만 낸다.
- 최종 파일 저장, 자기 시도 실패 확정 또는 협의 종료 뒤의 늦은 협의 메시지는 무시한다. 진행 중인 종료 응답이나 종합은 계속한다. 그 메시지만으로 열린 턴은 자기 최종 파일이 있거나 실패가 확정됐으면 발신 없이 종료 한 줄만 낸다. 협의 종료 기록만 있는 참여자는 그 턴에서 단독으로 마친다.

## 참여 노드 재수행

기동 재시도를 포함해 참여 노드의 재수행을 결정하면 팀장은 재지시·재기동 전에 `GRAPH.md`의 진행 조건 칸에 양쪽의 협의 종료를 기록하고, 결과가 미확정인 대기 상대에게 단독 마무리를 지시한다. 재수행 없이 한쪽 실패가 확정돼도 같은 방식으로 상대를 깨운다. 워커는 상대 메시지·초안을 읽기 전과 발신·대기 전에 종료 기록을 확인한다.

재수행·종합 프롬프트도 워커 브리핑 템플릿의 「협업」 절을 채워 현재 노드·시도·결과·실패 경로, 완료 통보·복구 견본, 늦은 메시지 처리와 1회 저장 규칙을 직접 전달한다. 재수행에서는 초안·상대 찾기·상대 발신·대기만 뺀다. 재수행자는 재지시 시점에 이미 인수된 상대의 최종 파일만 상대 의견으로 사용하고, 각자는 대조하지 못한 내용과 단독 판단을 최종 파일에 밝힌다. 원본 기준이 양방향 반론을 요구하면 단독 결과로 해당 기준을 통과시키지 않는다.

## 인수와 종합

팀장은 현재 행의 발신자·결과 경로와 일치하는 완료 통보 뒤에만 현재 실패·결과 경로를 써서 표준 절차로 노드별로 인수한다. 현재 실패 보고가 우선이며 종료 응답이 아직 없으면 최종 파일의 `## 결론`으로 원본 기준을 대조한다. 확정한 같은 시도를 다시 인수하거나 늦은 턴으로 판정을 바꾸지 않는다. 실패 분류와 재시도 예산은 기존 규칙을 적용한다.

팀장은 깰 때마다(다른 통보·사용자 메시지·재개 등) 미인수 참여·종합 노드의 현재 상태와 실패·결과 파일을 확인한다. 일반 대기 중에도 참여·종합 노드의 알림 없는 종료를 확인한다.

현재 최종 파일은 있으나 통보가 없고 워커가 `idle`이면 `send_agent_prompt`로 복구 요청을 한 번만 보낸다(재개 때도 현재 시도 발신 기록 확인). 복구 요청 뒤 전달·응답을 기다려 다시 확인해도 통보가 없거나, 통보 없이 워커가 `closed`·`error`면 그 시도를 실패로 확정해 `set`으로 상태와 진행 조건의 사유를 남긴다(`running`이면 `cancel_agent`로 현재 턴을 중단해 `idle` 확인 후 기록하며, 파일은 보존하고 인수하지 않는다).

두 참여자의 인수 또는 최종 실패가 확정되면 종합한다. 실패가 남으면 원본 기준이 부분 종합을 허용할 때만 인수한 입력으로 진행해 빠진 입력을 밝힌다. 팀장은 담당의 앞 턴이 끝날 때까지 기다리고 별도 종합 행과 결과·실패 경로·시도 번호를 지정한다. 행에 담당 `agentId`와 `실행 중`을 기록한 뒤 「협업」 절을 채운 종합 프롬프트를 같은 ID에 `send_agent_prompt`로 보낸다. 참여자 입력은 인수 파일 경로만 전달한다.

종합 담당이 첫 지시 전달 전후에 사용 불가해지면(지시 전달이 확정적으로 실패한 경우 포함) 해당 시도의 인수 가능 결과부터 확인한다. 실패 확정 뒤 남은 적격자로 담당 선정 규칙을 다시 적용한다. 대체 재수행은 기존 종합 행에 새 경로와 담당을 기록한 뒤 지시한다. 새 에이전트는 기동하지 않는다.

종합자는 인수 파일을 수정하지 않고 그 파일의 `파일:줄`만 근거로 인용한다. 단독 의견과 합의를 구분한다. 팀장은 종합을 인수해 결론과 실제 담당의 노드 ID·`agentId`를 보고한다.

## 재개

현재 시도의 파일과 인수 기록을 먼저 대조한다. 확정 판정을 유지하고, 미확정 통보는 현재 행과 통보·파일을 대조해 인수를 이어 간다. 종합이 `대기`면 입력·배정 요건을 확인한다. `실행 중`이면 해당 시도의 인수 가능 결과부터 확인한 뒤, 담당을 쓸 수 없으면(확정된 전달 실패 포함) 「인수와 종합」의 담당 사용 불가 처리를 적용하고, 담당을 쓸 수 있고 미전송이 확인된 경우에만 기존 배정을 이어 보내며, 전달된 지시는 인수·실패 판정으로 잇고, 전달 여부가 불명이면 중복 발신·배정을 보류하고 보고한다.
