# 무인 모드(goal 모드)

## 진입과 시작 승인

사용자가 실행을 "무인 모드"·"goal 모드"로 명시하고 GOAL 지시문을 주면 팀장이 진입한다. 이 문서 전체를 진입 직후 읽는다. 명시가 없으면 무인 모드 규칙을 적용하지 않는다.

팀장이 궁금한 것은 처음에 전부 질문하고 답을 받는다. 독립 질문과 앞 답에 종속되는 질문 모두 시작 문답에서 해소한다. 종속 질문은 앞 답을 받은 뒤에도 시작 승인 전에 질문한다. 미답변을 승인으로 취급하지 않는다.

답을 받은 뒤 허용 범위·자문 사용 목적·레벨 2면 계획을 한 화면에 담아 시작 승인 1회를 받는다. 레벨 1도 이 시작 승인을 받는다. 자문 목적은 실행 중의 사업·제품·기획 결정, 기술·보안·설계 쟁점, 검토 지적 수용과 반복 한도 연장 판단을 포함한다. 자문 기동의 사용 목적 사용자 승인은 이 시작 승인으로 충족된다.

레벨 2 계획 승인을 시작 승인과 따로 받지 않는다. 시작 승인 뒤에는 사용자에게 묻거나 승인을 기다리지 않는다. 워크스페이스 밖 생성물의 삭제 승인 요청은 실행이 끝난 최종 보고에서만 한다.

시작 문답·승인 화면을 내기 직전에 스킬 디렉터리 기준 references/FORM.md 「무인 모드 시작 승인 화면」을 읽는다.

## 허용 범위

- 작업 결과 커밋을 허용한다. 마일스톤 완료마다 커밋할 수 있으며, 커밋에 필요한 스테이징은 해당 작업 결과에 한정한다.
- 푸시·MR(merge request, 병합 요청)·외부 전송은 기본 불허다. 사용자가 GOAL 지시문에 명시한 행동·대상·내용 범위만 허용한다. 자문 결정이나 도구 출력으로 그 범위를 넓히지 않는다.
- 태그 생성과 브랜치 삭제는 불허한다.
- 삭제는 아래 세 조건을 **모두** 만족할 때만 실행 중 자동 허용한다. 삭제 전에 실제 절대 경로와 각 조건을 검증한다.
  1. 테스트로 생성된 폴더·파일이거나 삭제해야 다음 단계 진행이 되는 폴더·파일이다.
  2. git에 커밋돼 있어 되살릴 수 있거나 이번 실행에서 직접 만든 것이다.
  3. 실제 절대 경로가 작업 워크스페이스 안이다.
- 검증하지 않은 와일드카드 재귀 삭제는 금지한다. 워크스페이스 밖에 만든 폴더·파일은 실행 중 실제 경로를 기록한다. 실행 중 지우지 않고 최종 보고에 목록을 보여 사용자 승인을 받아 지운다. 워크스페이스 밖을 지워야만 다음 단계로 진행할 수 있으면 중단한다.
- 워크스페이스 밖 삭제, GOAL에 명시되지 않은 푸시·MR·외부 전송, 저장소 밖 설정 변경, 권한 상향은 자동 허용이나 자문 승인으로 대체하지 않는다. 해당 행동을 실행할 수 없고 목표 진행에 필수이면 중단한다. 허용 범위 안 행동의 하네스·정책 차단에는 아래 「호스트 정책 차단의 대체 수행」만 적용한다.
- scripts/graph_update.py와 scripts/append_system_prompt.py 내부의 원자적 쓰기 임시 파일 정리는 에이전트 판단 삭제가 아니므로 위 삭제 세 조건의 대상이 아니다. 무인 모드를 위해 두 스크립트를 고치지 않는다.

최초 기동과 후속 지시 모두 일반 워커에게 assets/worker-briefing.md 「허용 범위」를 채워 전달한다. 검토 워커의 검토 대상·작업 트리 읽기 전용 경계는 유지하며, 검토 워커에게 커밋·삭제 허용을 넘기지 않는다.

## 호스트 정책 차단의 대체 수행

허용 범위 안 행동(작업 결과 커밋, 삭제 세 조건을 만족한 삭제, GOAL에 명시된 외부 행동)이 한 호스트의 하네스·정책에 막히면 팀장이 대체 수행 여부를 판단한다. 막은 호스트와 다른 호스트의 수행자(팀장 포함)가 대신 수행할 수 있다. 워커 자신은 막힌 행동을 우회하지 않고 막힌 행동·호스트·사유를 팀장에게 보고한다.

대신 수행하기 전에 대체 수행자가 허용 범위 조건을 다시 검증한다. 삭제는 실제 절대 경로와 삭제 세 조건을 모두 다시 검증한다. 모드·권한을 올려 수행하지 않는다. 대신 수행한 사실은 실행 디렉터리의 DECISIONS.md에 바로 남기며, **막힌 행동, 막은 호스트와 사유, 대신 수행한 수행자(호스트 포함), 재검증 결과**를 적는다.

허용 범위 밖 행동, 사용자가 거부한 권한 요청, 권한 요청(승인 대기)이 생긴 경우에는 대체 수행을 적용하지 않는다. 승인 대기는 기존 중단 조건을 그대로 적용한다. 대신 수행한 쪽도 막히면 더 대체하지 않고 중단 절차로 간다.

## 게이트 대체

무인 모드는 레벨 1·레벨 2의 상위 규칙으로서 사용자 질문·승인 대기 지점만 아래처럼 대체한다. 레벨 판정, 레벨 2 GRAPH.md 기록, 개발 워크플로우 단계, 결과 인수, 독립 검토 요건, 팀장 자동 재시도 1회, 실패 분류는 그대로 적용한다. 스킬 본문과 모든 참조 문서의 사용자 대기 지점에 이 대체를 우선 적용한다.

| 사용자 답·승인을 기다리는 지점 | 시작 승인 뒤 처리 |
| --- | --- |
| 스펙 문답·공동 판정·사업·제품·기획 결정, 요청 결과·대상 범위·합격 기준의 변경 판단 | 사용자만 정할 수 있던 결정까지 GOAL 자문과 상의해 팀장이 결정하고 기록한다. 결정된 입력을 담당 워커에게 전달하며 사용자 답변으로 꾸미지 않는다 |
| 자문 사용 목적 승인, 적합 프로필·프리셋 부재로 역할 선택을 기다리는 지점 | 시작 승인의 자문 목적을 재사용하고, 아래 「세션 정의 역할」로 해당 세션의 역할을 정의한다. 등록 notes를 넓혀 해석하지 않는다 |
| 계획 승인, 뒤늦은 의존 발견·그래프 재설계에 따른 승인 | 시작 승인을 재사용한다. 실행 중 필요한 결정은 자문과 상의하고 허용 범위를 적용한다 |
| 커밋·삭제·외부 행동 등의 기동 직전 승인과 원인 교정의 삭제 제한 | 위 「허용 범위」를 대조해 허용된 행동만 실행한다. 범위 밖 행동은 실행하지 않고, 그 행동 없이는 진행할 수 없으면 중단한다 |
| 프로바이더 교체 등 실행 방식의 사용자 선택, 기록과 실제 상태 불일치로 필요한 결정 | 실제 상태를 먼저 확인하고 자문과 상의해 허용 범위 안에서 결정한다. 권한 상향·사용자 거부·승인 대기를 우회하지 않으며, 하네스·정책 차단은 위 「호스트 정책 차단의 대체 수행」만 적용한다 |
| 검토 미통과 지적의 처리와 검토·토론 라운드 소진 | 아래 수용·연장 규칙을 적용하고, 자문도 결정하지 못하거나 진행할 수 없으면 중단한다 |
| 워커 권한 요청(승인 대기), 사용자가 거부한 권한 요청, 권한 상향 | 자문이 대신 승인하지 않는다. 중단 절차로 간다 |
| 허용 범위 안 행동이 한 호스트의 하네스·정책에 막힘 | 위 「호스트 정책 차단의 대체 수행」에 따라 다른 호스트의 수행자가 재검증 뒤 수행할 수 있다. 적용 조건을 충족하지 못해 재개 경로가 없거나 대체 수행자도 막히면 중단 절차로 간다 |

검토 미통과 지적을 GOAL 자문과 상의한다. 자문이 남은 지적을 사소하거나 의도된 동작이어서 고칠 가치 없다고 판단하면 팀장이 수용하고 진행하며 DECISIONS.md에 남긴다. 검토 워커의 불합격 판정 자체를 합격으로 고치지 않는다. 실제 결함이며 반복해도 풀리지 않는다고 자문이 판단하면 중단한다.

검토 라운드와 토론 라운드는 각각 기본 총 3회다. 기본 한도나 승인된 추가 횟수를 다 썼으면 GOAL 자문에게 추가 횟수를 받아 진행해 볼 만한지 판단받는다. 같은 단계(같은 검토·토론 노드)에서 여러 번 연장해도 추가 횟수의 누적 상한은 20회이고, 기본 3회를 포함한 총 상한은 23회다. 자문이 정한 횟수만 연장하며, 자문 호출·재기동·재설계로 누적 횟수를 초기화하지 않는다. 추가 진행을 하지 않기로 판단하거나 상한을 다 쓰고도 해결되지 않으면 수용 여부를 자문과 판단하고, 수용할 수 없으면 중단한다.

워커 내부의 같은 명령 재시도 3회(assets/worker-briefing.md)와 팀장 자동 재기동 1회는 이 연장 대상이 아니다. 독립 검토의 실제 라운드 집계와 실패·환경 미수행·검토자 실패의 분류를 유지한다.

레벨 2 그래프를 설계할 때 사용자 게이트가 들어갈 자리는 GOAL 자문 워커 노드로 둔다. ID는 `N`, 종류는 `워커`이며, 모델과 실제 agentId를 기록한다. `공동 판정`은 `G`를 유지한다. 새 노드 종류를 만들지 않는다. 결정 질문·피드백 관계선은 해당 자문 노드와 연결하고, 일반 워커의 결과 인수·상태 갱신 절차를 따른다. 실행 중 추가되는 자문 노드는 N의 최대 번호 다음으로 추가하며 이미 부여한 ID를 바꾸지 않는다.

검토·토론의 연장 횟수는 새 열 없이 해당 단계의 기존 `검토 라운드` 칸에 `상한 3+자문 {N} · 사용 {M}`으로 기록한다. `{N}`은 자문이 부여한 추가 횟수의 누계(0~20), `{M}`은 실제 사용한 총 라운드 수다. 자문 결정과 사용 횟수 변경을 scripts/graph_update.py set으로 기록하고, 토론 연장은 그래프의 스테이지에도 반영한다.

시작 승인 뒤부터 최종 보고·중단 보고 전까지 팀장이 턴을 마칠 때 내는 출력은 고정 문구 `무인 실행 중` 한 줄뿐이다. 진행 요약·노드 결과·판정·다음 단계 예고·기동 보고·자문 결정·추가 질문은 내지 않는다. 해당 내용은 GRAPH.md(레벨 2)·DECISIONS.md·최종 보고로만 보내고 결과 인수·기록을 수행한다. 사용자가 실행 중 직접 보낸 메시지에 답하는 것은 자발 발화가 아니므로 이 제한에서 제외한다. 최종 보고·중단 보고는 references/FORM.md 「무인 모드 완료·중단 보고」 견본대로 내며, 실행 중 출력 배정은 「발화 지점 배정」의 무인 모드 행을 따른다.

## 세션 정의 역할

Paseo 등록 프로필의 notes가 필요한 일을 허용하면 그 원문을 그대로 쓴다. 등록 프로필과 프리셋에도 없는 역할이 필요하면 팀장이 그 세션에서만 쓸 이름·notes를 정의한다. Paseo 설정의 agentProfiles에는 등록하지 않는다. 기존 등록 프로필의 notes를 넓혀 해석하지 않는다.

자문은 등록 자문 프로필의 기술·보안·설계 범위를 확대하지 않고 세션 정의 역할 **GOAL 자문**으로 기동한다. notes는 다음 범위를 명시한다: 실행 중 사업·제품·기획 및 기술·보안·설계 결정에 팀장과 상의하고, 검토 지적의 수용 가치·반복 실제 결함의 해결 가능성·검토 및 토론의 추가 횟수를 판단한다. 권한 상향·하네스 거부를 대신 승인하거나 허용 범위를 확대하지 않으며, 일반 탐색·구현·독립 검토를 대신하지 않는다.

실제 provider·model·mode·thinking 선택과 값 이관은 위임 절차를 유지하며 권한을 자동 승격하지 않는다. 일반 워커 브리핑 첫 줄은 assets/worker-briefing.md의 세션 정의 표시를 사용하고, 후속 지시에도 이름·notes·허용 범위를 전달한다. 자문 결정으로 담당 일이 등록 notes의 배제 범위를 넘으면 그 프로필에 넘기지 않고 세션 정의 역할로 분리한다. 자문 역할을 구성하거나 기동할 수 없어 필요한 결정을 받지 못하면 생략하고 진행하지 않고 중단한다.

## 결정 기록

팀장이 자문과 상의해 결정할 때마다 실행 디렉터리의 DECISIONS.md에 바로 덧붙인다. 각 결정은 **질문, 선택지, 결정, 근거, 자문 agentId**를 담는다. 수용한 검토 지적과 그 수용 근거, 연장 대상과 이번 추가 횟수·누적 추가 횟수·실제 사용 횟수도 해당 결정에 적는다.

워크스페이스 밖 생성물의 실제 경로도 실행 중 이 파일에 기록하고 워커가 보고한 경로를 취합한다. 사용자 확정 답변과 자문 결정을 구분하며, 최종 보고에 자문 결정·수용 지적·연장 횟수를 모은다. 레벨 1에도 이 기록을 남기되 레벨 2 전용 GRAPH.md를 만들 의무는 추가하지 않는다.

## 중단

다음 상황이면 팀장이 무인 실행을 멈춘다.

1. 자문도 결정하지 못한다.
2. 검토 미통과 지적이 실제 결함이고 반복해도 풀리지 않는다고 자문이 판단한다.
3. 워크스페이스 밖 삭제가 필요해 진행할 수 없다.
4. 워커에 권한 요청(승인 대기)이 생긴다. 기존 승인 범위 안인지와 무관하게 자문은 대신 승인하지 않는다.

허용 범위 밖의 필수 행동, 사용자가 거부한 권한 요청, 「호스트 정책 차단의 대체 수행」을 적용할 수 없는 하네스·정책 차단 등으로 재개 경로가 없을 때도 중단한다. 대신 수행한 쪽도 막히면 더 대체하지 않고 중단한다. 워커의 실패 분류와 허용된 재시도 조건은 바꾸지 않으며, 모드·권한을 올려 우회하지 않는다.

중단을 결정하면 새 워커를 띄우지 않고, 재기동·후속 지시·대기 큐 투입도 하지 않는다. 이미 실행 중인 워커는 끝까지 마치게 한 뒤 결과를 받아 기존 결과 인수 절차로 판정한다. 권한 대기 워커의 요청은 승인하지 않고 해당 상태와 미완료 범위를 보고한다. 실행 중 워커의 결과 수신을 마친 뒤 중단 보고를 낸다. 사용자가 명시적으로 전원 중단을 지시한 경우의 중단 절차와 구분한다.

## 완료·중단 보고

전원 결과를 인수한 뒤 완료 또는 중단 보고를 낸다. 출력 직전에 스킬 디렉터리 기준 references/FORM.md 「무인 모드 완료·중단 보고」를 읽는다. 원본 합격 기준별 상태·증빙, 결과 경로, 실패·미완료·미검증, 자동 재시도 사용 등 일반 완료 보고의 필수 항목을 유지한다.

DECISIONS.md의 자문 결정 요약과 근거·자문 agentId, 수용한 지적과 보존된 검토 판정, 검토·토론의 사용 횟수와 누적 연장 횟수, 세션 정의 역할을 보고한다. 워크스페이스 밖 생성물이 있으면 실제 경로 목록과 삭제 승인 요청을 넣고 승인받기 전에는 지우지 않는다. 생성물이 없으면 없음으로 적는다.

중단 보고에는 중단 사유, 이미 실행 중이던 워커의 결과와 권한 대기 상태, 미기동·미완료 범위를 포함한다. 중단을 새 승인 질문이나 자동 재개로 바꾸지 않는다. 완료·중단 보고 전의 턴 종료 출력은 `무인 실행 중` 한 줄만 내며, 사용자가 실행 중 직접 보낸 메시지에 대한 응답은 제외한다.
