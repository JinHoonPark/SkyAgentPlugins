# 실패 시

실패는 아래 조건 중 하나다. 그 밖의 오류는 원인을 고쳐 계속하고, 다시 실행한 사실을 보고에 적는다.

되돌리기 어려운 단계는 git 커밋·스테이징·푸시·태그·브랜치 삭제, 외부 전송(업로드·배포 포함), 파일·디렉터리 삭제, 저장소 밖 설정 변경이다. 이 단계와 권한 상향은 기존 승인 경계를 따른다.

되돌리기 어려운 단계 **전**의 환경 오류·일시적 오류는 아래 고정 실패 조건의 예외인 「그 밖의 오류」로 처리한다. 환경 오류는 원인을 고쳐 계속하고, 일시적 오류는 최초 실패 뒤 같은 명령을 **최대 3회 재시도**한다. 이 3회는 워커가 같은 세션 안에서 명령을 다시 실행하는 횟수이며, 팀장이 노드를 새로 기동하는 SKILL.md 「위임 경로의 승인·판정 게이트」와 references/failure-handling.md 「재시도」의 자동 재시도 **1회**와 별개다. 팀장 기동 재시도 한도를 늘리지 않는다.

되돌리기 어려운 단계를 **실행하는 중·이후**의 오류는 멈추고 보고한다. 그 단계가 실행됐는지 알 수 없는 경우에도 다시 실행하지 않는다. 명시적 권한 거부와 대상의 실제 변경 상태를 알 수 없는 경우에는 위 예외를 적용하지 않는다.

단계 전 오류라도 원인 교정에 권한 상향·삭제·외부 전송이 필요하면 그 교정은 실패로 분류하고 실행하지 않는다. 해당 검증만 미검증으로 표시하고 사유를 실패 보고 경로에 남긴다. 그 검증 결과에 의존하지 않고 같은 승인 범위에서 안전하게 수행할 수 있는 나머지 작업은 계속한다. 권한 상향은 팀장의 기존 승인 절차를 따른다.

- 합격 기준을 검증했는데 대상이 기준을 충족하지 못한다.
  검사 방법 자체의 결함(검사 코드 오류, 비교 조건 실수 등)은 그 밖의 오류다.
- 원인을 고쳐 다시 시도해도 같은 원인으로 막힌다. 단계 전 환경 오류는 위 원인 교정 절차를 적용한 뒤, 일시적 오류는 허용된 3회 재시도를 소진한 뒤 이 조건으로 판정한다. 동시에 난 같은 원인의 오류는 한 번으로 센다.
- 합격 기준을 채울 방법이 남아 있지 않다.
- 권한 거부, 원인 교정에 권한 상향·삭제·외부 전송이 필요한 경우, 또는 되돌리기 어려운 단계를 실행하는 중·이후의 오류가 났다. 단계 전의 환경·일시적 오류는 위 예외 범위에서 처리한다.
- 대상이 의도와 다르게 바뀌었거나 바뀌었는지 알 수 없다.

위 실패 조건에 해당하는 작업·검증은 다시 실행하지 않고 **실패 보고 경로**에 실패 사유를 쓴다. 계속할 수 있는 나머지 작업의 범위는 위 단계 전 원인 교정 제한을 따른다. 되돌리기 어려운 단계 실행 중·이후에는 나머지 작업도 진행하지 않는다.
수정 대상 파일에는 실패 문구를 쓰지 않는다. 파일 기록이 불가능하거나 사용자가 쓰기를 금지한 경우, 파일 기록을 포기하고
짧은 응답으로 실패와 미검증을 보고한다.
