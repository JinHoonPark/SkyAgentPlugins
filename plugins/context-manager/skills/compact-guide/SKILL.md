# compact-guide

`/compact`는 대화를 요약해 컨텍스트를 줄이는 내장 명령이고, 뒤에 지침을 붙이면 요약이 그 지침에 맞춰진다. 지침 없이 압축하면 요약기가 무엇이 중요한지 몰라 승인 범위, 제약, 진행 중인 작업 같은 것이 흐려진다. 이 스킬은 현재 대화를 읽고 압축 뒤에도 남아야 할 것을 골라 지침으로 만든다.

`/compact`는 내장 명령이라 모델이 직접 실행할 수 없다. 지침을 만들어 보여 주는 데서 끝나고, 사용자가 그것을 입력창에 붙여 제출해야 압축이 일어난다. 압축을 실행했다거나 실행하겠다고 말하지 않는다.

## 절차

1. 현재 대화 전체를 훑어 아래 항목 중 **실제로 있는 것만** 모은다. 대화에 없는 항목을 채우려고 추측하거나 지어내지 않는다 — 없는 항목은 지침에서 뺀다.
   - 목표: 사용자가 이 세션에서 이루려는 것과 완료 조건
   - 사용자가 확정한 결정과 승인 범위: 무엇을 승인했고 무엇을 아직 승인하지 않았는지, 사용자가 명시적으로 거절하거나 금지한 것
   - 제약과 규칙: 사용자가 준 작업 방식 지시, 지켜야 할 프로젝트 규칙
   - 진행 중인 파일과 변경: 만들거나 고친 파일 경로, 각 변경의 요지, 아직 반영되지 않은 것
   - 검증 결과: 실행한 명령과 결과(통과·실패), 검증하지 못한 것
   - 미결 사항과 다음 작업: 답을 기다리는 질문, 남은 단계, 알려진 결함
   - 되살릴 수 없는 사실: 한 번 읽은 외부 문서의 핵심 값, 다시 얻기 어려운 식별자·경로·명령
2. 항목마다 압축 요약기가 그대로 보존할 수 있게 구체적으로 쓴다. "작업 중인 파일"이 아니라 파일 경로와 상태를 적는다. 결정은 결론만이 아니라 사용자가 한 말의 요지를 함께 적어, 요약 뒤에도 승인 여부가 바뀌지 않게 한다.
3. 되살리기 쉬운 것은 지침에 넣지 않는다. 파일 내용 전체, 긴 도구 출력, 이미 끝나서 영향이 없는 탐색 과정은 압축으로 사라져도 다시 읽으면 된다. 지침이 길수록 요약기가 핵심을 놓치므로 한 단락 안팎으로 유지한다.
4. 지침의 마지막에 "위 항목은 요약하지 말고 그대로 유지하고, 그 밖의 탐색·도구 출력은 간략히 줄여라"에 해당하는 문장을 넣어 무엇을 줄여도 되는지 알려 준다.

## 출력

사용자가 한 번 복사해 입력창에 붙여 제출할 수 있도록, `/compact`로 시작하는 한 덩어리를 코드 블록 하나에 담아 낸다. 코드 블록 안에는 `/compact`와 지침 본문만 두고 설명이나 번호 목록 머리말을 섞지 않는다. 지침 본문은 줄바꿈 없이 이어 쓰거나, 줄바꿈이 필요하면 빈 줄 없이 쓴다.

코드 블록 바로 뒤에 아래 두 가지를 짧게 덧붙인다.

- 이 지침은 `/compact`를 직접 제출해야 적용되며, 지금은 압축이 일어나지 않았다는 안내
- 지침에 넣지 않은 중요한 후보가 있거나 대화에서 확인하지 못한 항목이 있으면 그 사실. 없으면 생략

대화가 거의 비어 있어 보존할 것이 없으면 지침을 억지로 만들지 말고 그 사실을 알린다.
