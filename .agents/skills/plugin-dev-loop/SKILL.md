# Plugin Dev Loop

이 워크트리를 claude·codex 로컬 마켓플레이스로 점검·등록·설치·검증한다. `loop` 가 등록·설치·검증을 한 번에 돌린다. `check` 는 조회와 검증만, `register` 는 마켓플레이스 등록만, `restore` 는 스냅샷의 원본 등록으로 되돌린다. 실행 로직은 스크립트 한 벌뿐이다. CLI 명령을 손으로 조립하지 말고 아래만 부른다.

```powershell
python scripts/plugin_dev_loop.py <command>
```

경로는 이 스킬 디렉터리 기준이다. 절차·옵션·스냅샷 규칙은 `python scripts/plugin_dev_loop.py --help` 를 본다.

## 격리 환경

워크트리마다 격리 환경이 **자동으로 갈린다. 사용자가 지정할 것은 없다.** 전역 등록 상태가 하나뿐이라 워크트리끼리 덮어쓰지 않도록, git 워크트리 루트에서 경로를 유도한다. `--env`는 특별한 위치를 쓰고 싶을 때의 선택지다. 실행할 때 쓰는 격리 환경 경로가 한 줄로 출력된다.

## 실행 경로

확정된 실행 경로는 **셸에서 명령마다 `env`를 실은 비대화형 세션**이다. Paseo가 에이전트 세션에 격리 환경 변수를 주입하는 공식 경로가 없다. `codex exec`와 `claude -p`가 격리 환경을 정확히 읽는 것은 확인됐다.

## Codex 설치 검증

Codex 설치 검증은 자동화하지 않는다. 비대화형 Codex 세션은 `approval_policy=never`라 `plugin install`·`marketplace add` 같은 워크스페이스 밖 쓰기에서 승인 주체가 없어 거부된다. 전면 해제(yolo)는 쓰지 않는다. **머지 직전에 사람이 대화형 Codex 세션에서 한 번 확인한다.** 자동 경로는 `--agent claude`만 쓰고 Codex 등록·설치는 돌리지 않는다.

## 로드 확인

이 스킬이 로드됐는지 확인만 요청되면 `PLUGIN-DEV-LOOP-LOADED`만 답하고 스크립트를 실행하지 않는다.

## 승인

등록·설치·되돌리기를 실제로 바꾸는 명령은 `--yes`가 필요하다. 먼저 `--yes` 없이 계획을 실행하고, 출력의 현재 경로와 변경을 그대로 보여 준 뒤, 사용자가 그 변경을 명시한 다음에만 `--yes`를 붙인다. "테스트해줘"·"확인해줘"·무응답은 승인이 아니다. `--yes`를 임의로 붙이지 마라.

원래 소스를 복원할 수 없으면 스크립트가 retarget을 거부한다. `--yes`가 있어도 거부한다. 격리 환경 하위에 junction·symlink·reparse point가 있으면 등록·설치·restore를 `--yes`가 있어도 거부한다. 출력된 비재귀 제거 명령만 사람이 실행하고, 에이전트는 링크를 제거하지 않는다. 테스트가 끝나면 `restore --yes`로 원본 등록을 되돌린다.

## 실행 완료 확인

실행 도구가 session_id를 반환하면 명령은 아직 실행 중이다. 프로세스 종료와 종료 코드를 확인하기 전에는 `restore`, 정리, 겹치는 실행을 하지 마라. 종료 코드를 확인할 수 없으면 스냅샷과 임시 파일을 남기고 경로를 보고하라.

## 정리

격리 환경 정리는 반드시 아래 명령으로만 한다. 셸에서 삭제 명령을 직접 구성하지 않는다.

```powershell
python scripts/plugin_dev_loop.py cleanup-env --yes
```

`init-env`·`cleanup-env`·`check`·`loop`·`restore`는 `--env` 없이 이 워크트리 경로로 유도한다. 변경 명령(`init-env`·`cleanup-env`)은 `--yes`도 받는다.

## 하지 않는 것

- `plugins/` 아래와 네 매니페스트를 고치지 않는다.
- git commit·staging·push를 하지 않는다.
- 설치본 캐시를 직접 고치지 않는다.
- 사용자가 승인한 계획에 없는 마켓플레이스 remove/add를 하지 않는다.
